# 论文结构与逻辑：六维诊断规则（references/review-rules.md）

本文件是 SKILL.md 第 4 节执行流程的方法细则。脚本只负责抽取候选锚点（sections、
numbers、claims、citations），结构判断由模型按本规则完成；模型**只核对、不凭空生成**，
每个判断必须携带 locator + 逐字 quote 才能写入 result.json.sources。

## 1. 六维框架与问题类型

| 维度（dim） | 考察内容 | 典型问题类型 |
|---|---|---|
| `research_question` 研究问题与贡献对齐 | 研究问题是否清楚提出、贯穿全文；贡献主张是否与实际完成工作一致 | 问题缺失、问题漂移、贡献夸大、问题与方法脱节 |
| `chapter_structure` 章节结构与叙事顺序 | 章节顺序、篇幅分配、信息释放顺序是否服务论证 | 铺垫缺失、细节前置、章节应合并/应拆分、信息顺序颠倒 |
| `argument_chain` 论证链与论据对应 | 每条论断是否有支撑论据；是否存在断裂、跳跃、循环论证 | 论断无据、论据不足、逻辑跳跃、循环论证、以相关性当因果 |
| `paragraph_relations` 段落关系与过渡 | 段落之间是否缺过渡、逻辑跳跃、上下文断裂 | 缺过渡句、段落拼接、语义断层 |
| `duplication` 重复内容 | 同义重复、跨章节重复表述 | 冗余复述、跨章重复、可合并段落 |
| `conclusion_boundary` 结论边界与表述尺度 | 结论是否超出数据与实验条件允许范围、是否遗漏限制 | 边界越界、缺限制说明、因果误述、过度概化 |

## 2. 问题定位与溯源（说得清 / 可核验）

每个 finding 在 result.json.sources 中的记录格式：

```json
{
  "finding_id": "F01",
  "dim": "conclusion_boundary",
  "problem_type": "因果误述",
  "locator": "manuscript.md §5.1 结论第2段 第3句（L42-L44）",
  "quote": "综上，A 显著提高 B，因此 A 是 B 的原因。",
  "evidence": "原文只有相关性统计（r=0.61, p<0.05），无干预/时序设计",
  "severity": "high",
  "action": "将'是……的原因'收窄为'与……显著相关，提示可能的方向，因果需进一步设计验证'",
  "disposition": "建议采纳",
  "confidence": "high"
}
```

硬性要求：

- `locator` 必须落到"文件 + 章节/段落/句子（可含行号）"，不能只有文件名。
- `quote` 必须是原文**逐字**片段（≤400 字符），不能改写、不能概括。
- `evidence` 写明该判断的依据（原文依据或"缺失的论据"），不新增材料外事实。
- `confidence` 用 high/medium/low，只按证据强度标注。

## 3. 可执行编辑动作（改得动）

编辑动作必须是**具体指令**，不是另起一篇改写稿。动词表：

- 移动：`将 §3.2 第2段移动到 §1.3 之后，作为研究问题的引出`。
- 合并：`将 §2.1 与 §2.2 合并，二者重复描述同一方法`。
- 拆分：`将 §4.1 拆为"结果陈述"与"机制讨论"两段`。
- 收窄：`将"证明了因果"收窄为"观察到相关性，因果待验证"`。
- 补据：`在论断 X 后补充图3/表2 的数据支撑或标注'无直接论据'`。
- 删重：`删除 §5 第3段，与 §3.2 第1段同义`。
- 加限制：`在结论末尾补充样本量、单中心、非随机化的限制说明`。

每条动作给 `disposition`：`建议采纳` / `部分采纳` / `驳回`，并说明理由，方便作者复核。

## 4. 论点—论据映射（链得通）

逐条抽取"研究问题 → 方法 → 结果 → 结论"的论断，映射到支撑论据，输出
`source_map`（结构化数组），每项：

```json
{"claim": "本方法在 X 数据集上准确率最高",
 "claim_locator": "§4.2 L10",
 "evidence": ["表2 中准确率 92.3% 高于基线 88.1%"],
 "evidence_locator": ["table2 第3行"],
 "link_verdict": "sufficient | insufficient | gap | loop | leap"}
```

`link_verdict` 五选一：`sufficient`（论据足够）、`insufficient`（论据不足）、
`gap`（断裂/无据）、`loop`（循环论证）、`leap`（跳跃）。闭环核对必须覆盖
研究问题是否被结论回答、方法是否匹配问题、结果是否支撑结论。

## 5. 结论边界检查（说法尺度）

对结论句逐条检查：

- 是否把相关性表述成因果（`与……相关` vs `导致/引起/是……的原因`）。
- 是否超出数据范围（样本、种群、条件、时长、地域）。
- 是否遗漏限制说明（样本量、单中心、回顾性、非随机、多重比较）。
- 是否用"证明/证实"表达只有初步证据的结论——证据不足时降为"提示/初步表明"。

## 6. 严重度与优先级

- `high`：影响结论成立或研究问题闭环，必须改。
- `medium`：影响可读性或论证链局部，应改。
- `low`：重复/过渡/表述尺度等，可改。
同 severity 内按"先论证链、后结论边界、再结构、最后语言"排序；语言润色问题
**不进入** finding，除非它改变了事实含义。

## 7. 降级与缺口标注

- 缺章节、无参考文献、图表与公式缺失、稿件截断：在 `uncertainty` 与
  `version_boundary.limitations` 标注，dim 相应记为"无法检查"。
- 图表/公式无法读清：不猜，正文用"[待确认：xxx]"，`confidence` 标 `low`。
- 材料不足：status 置 `insufficient_evidence` 或 `partial`，不补造内容。
- 冲突信息：两个来源不一致时两条都记录并标 `source_conflict`。
