# 自检清单（checklist）

交付前逐条勾选。每条对应一个评分维度；未满足的项不得标记完成。

## 实际效果（40 分）

- [ ] 已对一篇完整稿件产出结构诊断，并交付作者可直接执行的修改方案（任务完成度）。
- [ ] 每条诊断都能指回原文 locator + 逐字 quote；判断与原文实际内容相符，未虚构缺陷、
      未漏掉真实断裂、未把风格偏好误判为结构错误（正确性）。
- [ ] 六维——研究问题对齐、章节结构、论证链、段落关系、重复内容、结论边界——均已评估；
      某维不是稿件主要问题时写明"未发现主要问题"而非留空（完整性）。
- [ ] 每条诊断与每条编辑动作都可独立复核：作者能据此判断采纳/部分采纳/驳回（可核验性）。

## 使用增益（25 分）

- [ ] 起草前已运行 `scripts/main.py` 生成骨架与 evidence.json，候选锚点来自脚本而非记忆
      （质量/效率）。
- [ ] 骨架先行、增量改进；每次增量写 change_log，返工次数可查（增益可验证）。

## 创新增益（15 分）

- [ ] 论点—论据映射：逐条论断列出来源位置与论据强度（新增能力）。
- [ ] 跨章节冗余检测与结论—数据范围边界比对由脚本提供候选、Agent 核对（方法改进）。

## 可靠体验（10 分）

- [ ] 触发条件明确、脚本可用、路径有效；`python scripts/main.py --help` 退出码 0（易用/稳定）。
- [ ] 空输入、坏 JSON、缺章节、无参考文献、图表缺失、稿件截断等已识别并降级，未编造
      （异常处理）。

## 生态贡献（10 分）

- [ ] SKILL.md 说明用途、适用条件、调用方式、输入输出、异常处理与限制（文档完整）。
- [ ] 六维问题类型表、编辑动作分类、论断语气映射与脚本可被他人复用（可复用性）。

## 落盘前的最终校验（脚本可自动完成）

- [ ] `python scripts/main.py` 已运行，`/app/output/result.json` 合法且字段完整。
- [ ] `python scripts/selftest.py` 全 PASS。
- [ ] `python scripts/main.py` 的 verify 步骤无 error（warning 可接受并已写入 uncertainty）。
- [ ] case_id 取自 case.json，output_contract 键原样回填，无改名/删键。
- [ ] status 诚实：complete 必须六维均评估；否则 partial，并把限制写入 uncertainty 与
      version_boundary.material_gaps。

## 六维快速判据（供作者与复核人独立使用）

判据核心是"是否影响论证成立、信息顺序、逻辑闭环或结论有效性"，影响则判结构问题，
否则判风格偏好、不写入诊断。下表每维各给一个结构问题例与一个"非结构问题"反例。

| 维度 | 结构问题例 | 非结构问题（不判） |
|---|---|---|
| 研究问题对齐 | 引言未提可验证问题，结论却宣称验证了某假设 | "本研究旨在……"措辞不够生动 |
| 章节结构 | 结果先于方法出现，读者无法理解结果来源 | 某段句子偏长 |
| 论证链 | 结论称"X 导致 Y"，全文只有相关数据 | 用词重复但论据链完整 |
| 段落关系 | 相邻两段从方法直接跳到结论，缺结果支撑 | 两段语气不够统一 |
| 重复内容 | 方法、讨论、结论无差别复述同一段结果 | 摘要与结论各用一句重申核心发现 |
| 结论边界 | 单中心 n=40 的结论推广到全体患者 | 结论写得保守但句法冗长 |

## 判据执行顺序（每条 issue 走一遍）

1. 定位：locator 是否精确到段/句，quote 是否逐字；
2. 定性：属于六维中哪一维、哪一 issue_type；
3. 排除：是否只是风格偏好（用上表反例排除）；
4. 闭环：该论断是否有论据，论据强度是否支撑措辞；
5. 边界：结论是否超出数据/实验条件范围；
6. 可执行：给出 type+target_locator+action+priority+acceptability，作者可据此操作。
