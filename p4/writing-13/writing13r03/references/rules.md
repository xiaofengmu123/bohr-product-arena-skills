# 规则：事实-来源映射、七要素判据与不编造红线

## 1. 事实-来源映射规则

- 每个关键结论、数字、术语、引用、图表、前期成果、政策口径都必须登记进台账（`scripts/ledger.py add`），并带 `source_ref`（文件:页）、`locator`（段/表/图）、逐字 `quote`。
- `status` 三态：`mapped`（已定位到来源且有逐字 quote）、`unmapped`（材料中找不到来源，写 `note` 说明原因）、`conflict`（两个来源不一致，两条都登记，`note` 记录双方依据）。
- `temporal` 三态：`已完成`（申请人前期成果/平台条件/已发表文献）、`拟开展`（本研究将做的事）、`未知`（无法从材料判断）。**已完成/拟开展不得混淆**；"拟开展"或"未知"的内容不得作为研究基础或已获成果写入正文。
- 逐字 quote 必须来自实际读到的材料文本；不得改写字句后仍标为 quote。无法逐字提取（如图表数值）时，quote 写"图表: <原样描述>"并在 `locator` 指到图/表编号。
- 每条记录可带一致性链接：`goal_ref` / `content_ref` / `route_ref` / `metric_ref`，用于"研究目标↔研究内容↔技术路线↔考核指标"的一一对应回检。链接应两两完整，不允许孤儿项。

## 2. 七要素与四个判据（领域专精）

**七要素**：①立项依据 ②科学问题 ③研究目标 ④研究内容 ⑤技术路线 ⑥创新点 ⑦研究基础与可行性；外加跨要素锚点 **考核指标**。

**四个判据（可观察、可操作）**：

- **立得住**：立项依据必须包含"领域现状→关键瓶颈→申请人前期观察→必要性结论"四环，回答"别人做到哪一步、还差什么、为什么是我们"；每一环有 `source_ref`。禁止把研究意义写成政策口号堆叠（判据：意义段落若不含具体瓶颈/差距/前期观察，判为不通过）。
- **说得准**：创新点逐条对应具体已有工作（`kind=引用` 台账记录），写清"新在哪里、为什么难、凭什么做得成"；禁止无来源支撑的"首次/国际领先/填补空白/国际首次/世界领先/首创"。
- **对得上**：研究目标、研究内容、技术路线、考核指标逐条一一对应。`element_matrix.md` 的一致性矩阵不得有孤儿行/孤儿列；每个目标至少挂一条内容、一条路线步骤、一条可考核指标。
- **查得到**：文献、数据、前期成果、政策口径逐条回溯；区分"已完成"与"拟开展"。

## 3. 体裁/格式/引用规则

- 以 task.md 指定的体裁、受众、格式、字数、语言、引用风格为最高优先级；任务未指定时默认产出：`manuscript.md`（可直接进入申请书的章节稿）+ `element_matrix.md`（要素对照说明）。
- 章节稿按七要素组织，每段末尾或段内以脚注/括号方式给出可复核定位（如 `[来源: 材料名:页]`），与台账 `source_ref` 对齐。
- 引用格式：使用材料中实际出现的文献信息；不得补充材料之外的 DOI、卷期、页码或作者。材料缺失的元数据写 `pending_human`，不得编造。
- Office/slide/diagram 产物另附真实渲染的 PDF/PNG 预览，并在 `artifact`/`sources` 注明；无法渲染时在 `uncertainty` 写明。

## 4. 不编造红线（违反即失格）

- 不编造 benchmark 分数、实验数据、DOI、卷期页码、图表内容、引用文献或运行结果。
- 不把文件名/领域标签当事实；不依据错误的领域标签补造数据。
- 不把 `in_progress`/`partial` 写成 `done`；不把"拟开展"写成"已完成"。
- 不预写正式测试答案/白板；不提交隐藏测试或白板（平台提供）。

## 5. 冲突与复现规则

- 同一指标两个来源不一致：两条都登记为 `conflict`，`note` 记录双方依据，不擅自选一、不擅自改分。
- 复现要求：第三方按同一材料、同一 `element_matrix.md`、同一台账、同一脚本，应重算同一结论。为此 `result.json` 记录 `runtime.input_digest` 与 `runtime.result_digest`。

## 6. 确定性规则

- 所有 JSON 用 `sort_keys=True`、固定缩进写出；目录枚举排序；不写墙钟时间、随机数、环境相关的绝对路径。
- `change_log` 用步序号（step 0/1/2…）而非时间戳；同一输入两次运行产物逐字节一致。
- 如需记录人读时间，写到 `/app/work` 的旁注文件，不得进入 `/app/output/result.json` 的可比对内容。
