# 基金申请书写作规则：七要素、四问、三级对应

本文件是 SKILL.md 的细则：把"准确、完整、可编辑、可复核"翻译为可观察判据。所有规则以 /input 实际材料为唯一事实来源。

## 1. 七要素与可观察判据

| 要素 | 写什么 | 合格判据（可观察） |
|---|---|---|
| 立项依据 | 领域现状→关键瓶颈→为什么是我们 | 三段各含 ≥1 条引用到材料的事实；无口号堆叠（口号无数据支撑即不合格）；"别人做到哪一步、还差什么、为什么是我们"逐句可回答 |
| 科学问题 | 1 个可回答、可分解、有边界的主问题 + ≤3 个子问题 | 主问题可一句话陈述；子问题与研究内容一一对应；无"问题过大或与研究方法错位" |
| 研究目标 | 2–4 个、层次清楚、可考核 | 每个目标对应 ≥1 条研究内容与 ≥1 条可测量考核指标 |
| 研究内容 | 与目标一一对应的"做什么" | 每条内容含输入/输出/方法/预期结果；非方法名罗列 |
| 创新点 | 对照已有工作的差异 | 每个创新点写清：已有工作(引材料)+其局限+我们做什么+为何难+凭什么做得成；禁用"首次/国际领先/填补空白"等无证据修饰 |
| 技术路线 | 按内容组织的步骤、方法与关键节点 | 路线条数与目标条数一致；每个关键节点有可验证产出；写输入输出、可行性依据、风险与备选方案 |
| 研究基础与可行性 | 能力—证据—与本项目关系 | 每条前期成果/平台/分工给出材料内证据引用，并说明与本项目直接关系；"已完成"与"拟开展"分开 |

默认七要素列表：立项依据、科学问题、研究目标、研究内容、创新点、技术路线、研究基础与可行性。若 case.json / organizer-workorder.json 显式给出不同要素，以其为准。

## 2. 四问（评审人视角自检）

- **立得住**：必要性论证是否构成"现状→瓶颈→为什么是我们"证据链，而非政策口号堆叠。
- **说得准**：创新点是否与具体已有工作对照，是否清除了无法核验的修饰。
- **对得上**：研究目标、研究内容、技术路线、考核指标逐条对应，无"目标 3 条、路线 2 条、指标另说一套"。
- **查得到**：引用文献、数据、前期成果、政策口径可追溯到材料来源，并区分"已完成"与"拟开展"。

每问须给出基于材料的可观察结论（哪句话的证据在材料哪一位置），不得只写"已保证准确/完整"。

## 3. 三级对应（段落↔要素↔证据）

- 每个正文段落标注所属七要素（写入 element_map）。
- 每个关键论断（数字/术语/引用/图表/关键判断）在 fact_source_map 中登记：element、claim、locator（文件:页/节/段）、quote（逐字引用）、temporal、status。
- 第三方据此判断"这句话该不该这么写"；未登记断言不得进入正文。

## 4. 时间态标注（temporal）

- **已完成**：材料中出现的前期成果/数据/已发表工作。正文写"已完成"并给 locator。
- **拟开展**：本申请拟做的事。正文用计划/将来语气，不得写成已完成事实。
- **材料外**：材料没有的断言。不得作为事实写入正文；确需写时标 pending_human，不得补造。
- **缺失**：材料缺口。写入 version_boundary.material_gaps 与 uncertainty。

## 5. 一致性矩阵（consistency_matrix）

- 行 = 研究目标编号，列 = 研究内容 / 技术路线 / 考核指标。
- 逐格填写对应关系；空单元格 = 错位，写入 mismatches 并说明原因。
- 收尾时回检：目标数 == 路线条数 == 指标条数，且逐条可映射。

## 6. fact_source_map 字段

- element：七要素之一。
- claim：关键论断原文/概括。
- locator：来源文件 + 页/节/段。
- quote：材料中逐字片段（必须逐字）。
- temporal：已完成 / 拟开展 / 材料外 / 缺失。
- status：mapped（已定位）/ unmapped（未定位）/ conflict（与另一来源冲突）。

## 7. 不编造红线

- 不虚构数字、引用、DOI、卷期页码、图表内容、实验数据、评分或运行结果。
- 不把文件名/领域标签当事实；只读实际文件内容。
- 材料缺失时写"缺失/材料外"，不补造；冲突时记录双方依据，不擅自选一。
