# 基金申请书七要素与四闸门写作规范

本文件是基金申请书写作 Skill 的核心判据来源，供 Agent 在起草、自检与降级时逐条对照。所有判据都是**可观察、可操作**的，不依赖"准确、完整"这类泛化表述。

## 1. 七要素（写作覆盖检查的锚）

基金申请书正文应覆盖以下七个要素，每个要素只写其应写的内容，不串位：

| 序号 | 要素 | 写作任务 | 完成判据（可观察） |
|-|-|-|-|
| ① | 立项依据 | 说明"为什么值得做、现在为什么必须做" | 至少含三条：领域现状(带引用)、关键瓶颈(具体到"别人做到哪一步、还差什么")、申请人前期观察与该瓶颈的关联 |
| ② | 科学问题 | 把研究兴趣收敛为可回答、可分解、有边界的问题 | 问题以问句或"本课题拟回答……"形式给出，且能拆成 2–4 个可验证子问题 |
| ③ | 研究目标 | 数量适度、层次清楚、可考核 | 目标数 = 内容数 = 路线数，每个目标可被指标检验，不含"揭示规律""深入理解"这类不可测目标 |
| ④ | 研究内容 | 按研究目标展开的具体工作 | 与目标一一对应，写明"做什么、为哪个目标服务"，无孤儿目标 |
| ⑤ | 创新点 | 与具体已有工作的差异，而非自我褒奖 | 每个创新点点名至少一项已有工作，写清"新在哪里、为什么难、凭什么做得成" |
| ⑥ | 技术路线 | 按内容组织步骤、方法与关键节点 | 每步有输入输出、可行性依据、风险与备选方案，不是罗列方法名 |
| ⑦ | 研究基础与可行性 | "能力—证据—与本研究的关系"证据链 | 前期成果、平台条件、团队分工都标注证据来源，并区分"已完成/拟开展" |

**考核指标** 不作为第八要素，而是"对得上"一致性检查的锚点：它必须与目标、内容、路线逐条对应。

## 2. 四闸门（立得住 / 说得准 / 对得上 / 查得到）

### 2.1 立得住（必要性成立）

- 必须出现"别人做到哪一步、还差什么、为什么是我们"三步论证，缺一步即判 `unmapped`。
- 禁止政策口号堆叠：把"国家重大需求""国际前沿"作为唯一理由而无具体瓶颈，记为 `anomaly`。
- 判据：立项依据段落里，每个"意义句"能否指回一项具体瓶颈或前期观察。

### 2.2 说得准（创新点精确）

- 禁止无证据的"首次""国际领先""填补空白""国内外率先""颠覆性""唯一"等不可核验修饰词。
- 命中规则：`scripts/core_impl.py` 的 `check_unverifiable_superlatives` 会逐句扫描；命中即标 `需核验`，若来源材料确实含该表述则保留并注明出处，否则改写为可核验的差异表述。
- 判据：创新点段落里每个"新"字能否用"与 X 工作的差异是 Y"重述。

### 2.3 对得上（目标—内容—路线—指标一致）

- 目标数、内容数、路线数必须相等；每个目标有可考核指标；无孤儿条目。
- 一致性矩阵写法：`work/correspondence.json` 存四组列表（可含编号），`scripts/main.py run` 自动比较数量与命名。
- 判据：第三方读完后能画出一张"目标→内容→路线→指标"的一一对应表。

### 2.4 查得到（事实可追溯）

- 每个数字、术语、引用、图表、关键论断都有一条 `fact_source_map` 记录。
- 每条记录必须带 `locator`（文件:页 + 段/表/图）+ 逐字 `quote`；引用文献与政策口径区分"来源原文"与"申请人转述"。
- 明确区分 **已完成**（前期成果、已发表数据，证据在前瞻材料里）与 **拟开展**（本课题计划做、尚无证据）。

## 3. 三级对应（段落 → 要素 → 证据）

评分要求"段落、要素与证据之间构成可复核的三级对应"。落地规则：

1. 正文每个小节的标题即要素名（`# 立项依据` 等）。
2. 正文中每个事实句编号（如 `[S3]`），对应 `fact_source_map` 里一条记录。
3. 每条记录的 `element` 字段写所属要素，`source_ref` 写来源文件，`quote` 写材料逐字片段。

示例（示意，非正式案例结果）：

```json
{
  "claim": "已有方法 A 在噪声大于 30dB 时精度下降 40%",
  "kind": "number",
  "element": "立项依据",
  "source_ref": "materials/paper1.pdf:p3",
  "locator": "第3页 结果段落",
  "quote": "accuracy drops by 40% when noise exceeds 30 dB",
  "tense": "已完成",
  "status": "mapped"
}
```

## 4. 已完成 / 拟开展 的判定规则

| 情形 | 归属 | 写法要求 |
|-|-|-|
| 材料中已有结果、数据、发表论文、专利、平台实拍 | 已完成 | 保留原数字与出处，动词用完成时 |
| 本课题计划完成、假设、设计目标 | 拟开展 | 动词用"拟/将"，不得写成已完成，`tense="拟开展"` |
| 材料未给出、无法判断 | 缺数据 | `status="unmapped"`，写入 `uncertainty` 与 `pending_human` |

## 4b. 四闸门通过/不通过对照示例（可观察判据）

以下均为**示例句**，仅演示判据如何使用，不构成任何正式案例的答案。

### 立得住
- ❌ 不通过：「本课题符合国家重大战略需求，具有重要科学意义。」（只有口号，无瓶颈）
- ✅ 通过：「现有方法 A 在样本量 <100 时误检率升至 31%（文献 [1] 表 2），而申请人前期 47 例样本显示按特征 X 分组可将误检率压至 9%，说明瓶颈在样本量敏感性，本课题由此切入。」

### 说得准
- ❌ 不通过：「本课题首次在国际上填补空白，达到国际领先水平。」（不可核验修饰词）
- ✅ 通过：「与 A 组 2024 年提出的端到端模型（仅在固定噪声下训练）不同，本课题引入随噪声强度自适应的归一化层，难度在于需同时保持低噪声下精度不降，前期 31 组消融实验已初步表明可行。」

### 对得上
- ❌ 不通过：目标三条（目标一/二/三），路线只写两步，指标另说一套（三个目标但只有两个指标且命名对不上）。
- ✅ 通过：目标一 ↔ 内容一 ↔ 路线一 ↔ 指标一（阈值 9% 以内），数量与命名逐条一致；`work/correspondence.json` 四组列表数量相等。

### 查得到
- ❌ 不通过：「相关研究表明该指标可提升 30%。」（无出处、无法回溯）
- ✅ 通过：「该指标提升 30%」对应 `source_ref="materials/paper2.pdf:p5"`、`quote="the metric improved by 30%"`、`tense="已完成"`。

## 5. 与评分维度的对应（本 Skill 的设计取舍）

| 评分维度 | 本 Skill 的落实 |
|-|-|
| 任务完成度(15) | 七要素章节稿 + 要素对照说明，`artifact.path` 指向真实可编辑 `.md` |
| 结果正确性(15) | `fact_source_map` 每条带 `source_ref`/`quote`/`tense`，`unmapped`/`conflict` 单独说明 |
| 结果完整性(5) | 七要素齐全 + 考核指标对齐 |
| 结果可核验性(5) | `sources` 含 SHA256，`change_log` 完整 |
| 质量增益(15) | 四闸门是可观察判据，不是泛化描述 |
| 效率增益(5) | 骨架先行 + 台账增量，`change_log` 体现改进 |
| 增益可验证性(5) | 结论基于材料证据与来源映射 |
| 新增能力/方法改进(5+5) | 把评分要求译成可观察判据；从一致性分歧反推要素缺陷 |
| 创新证据(5) | `uncertainty`/`limitations` 写清边界与失效条件 |
| 调用易用/运行稳定(3+4) | 新评分员按文档独立跑通；脚本仅标准库、路径相对、重复运行一致 |
| 异常处理(3) | 题面歧义、材料缺失、超长输入、坏编码均有记录 |
| 文档/可复用/分享价值(3+4+3) | SKILL.md + 两个 references 齐全，台账/快照/自检可复用 |
