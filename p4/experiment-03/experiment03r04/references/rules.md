# 规则与检查清单

## 1. 关键参数识别与可行域

- 从设备手册、材料规格、安全阈值、历史记录中抽取**有限定义域**：上下限、步进、互斥关系。
- 每个参数必须落到 `{name, unit, suggested_value, min, max, step}`，并尽量给出
  `device_limit` / `material_limit` / `safety_limit` 硬约束。
- 建议值必须在 `[min, max]` 内，且不得越出三类硬约束；冲突（如目标温度 > 材料耐温）必须显式记录，
  通过降级（降目标、换材料、转人工）处理，禁止悄悄改约束。

## 2. 响应指标口径

- 写清：单位、测量方法、方向、目标、可接受下限、预测方式（历史拟合 / 代理模型 / 经验规则）、不确定度。
- 单指标不结论：转化率与选择性/副产物同时记录；成本与时间也是被优化的目标，不是事后注释。

## 3. 搜索策略

- 在网格 / 序贯 / 贝叶斯 / 分阶段筛选之间选择，写明：初始点怎么选、每轮补哪些点、如何用上一轮结果调整、
  收敛与停止判据。
- 候选点可由 `python scripts/main.py doe --work /app/work --seed 0` 确定性复现（固定随机种子）。

## 4. 成本与时间权衡

- 把机时、耗材、样品数、通量纳入 `cost_budget`；说明成本受限时“牺牲多少响应指标可接受”，
  以及多目标取舍逻辑（如：最多牺牲 2% 转化率换 1 h 机时）。

## 5. 风险与异常处置（逐条覆盖）

无可行解、约束冲突、数据缺失、设备报错、指标互相矛盾。每种情况给出：降级 / 转人工 / 终止的判断。

## 6. 证据溯源（硬要求）

- 每个关键结论/数值/参数建议值都要能指回材料中的逐字片段：`locator + quote`。
- 证据等级：`quoted`（逐字来源）> `derived`（由材料推导）> `assumed`（假设）> `pending`（待确认）。
- 冲突信息不隐藏：同一指标多来源不一致时都记录并标 `source_conflict`。
- 不虚构引用、DOI、数值；缺失写 `not_reported` 或进入 `pending_human`。

## 7. 降级与不确定性（本版侧重点）

- **缺数据**：不能确定的参数/响应/约束写入 `uncertainty` 与 `limitations`，`status=insufficient_evidence`；
  绝不编造数值或来源。
- **缺软件**：脚本仅依赖标准库；若 PDF/PNG 预览工具缺失，`artifacts` 只保留真实生成的格式并在
  `limitations`/`degradations` 说明，不伪造导出记录。
- **输入损坏**：坏 JSON/坏编码捕获到 `errors`/`degradations`，继续处理其余材料；全部不可读则 `input_error`。
- **时间/请求不足**：前 3 分钟先落盘 partial 骨架，之后按 A→B→C→D 增量改进；超时即停止并保留当前结果。

## 8. 交付前自检（对应评分维度）

- [ ] 已实际读取 `/input/case.json` + `task.md` + 材料内容（非仅文件名/标签）
- [ ] 关键参数含名称/单位/建议值/可行区间/步进，且全部落在设备量程/材料限/安全阈值内
- [ ] 每条参数有约束来源与逐字 quote，或显式标注 `evidence_level=assumed/pending`
- [ ] 响应指标含口径/单位/方法/方向/目标/可接受下限，预测方式与不确定度已披露
- [ ] 搜索策略写明初始点、每轮补点、收敛与停止判据；候选点可由 `doe` 复现
- [ ] 成本与时间预算有明细口径，多目标取舍说明“牺牲多少可接受”
- [ ] 覆盖假设、变量、对照、步骤、参数、资源、判读标准
- [ ] 风险与异常处置覆盖五种异常；确认项已列，未确认内容标 `pending_human`
- [ ] `result.json`：`case_id` 正确、`status` 如实、`sources/uncertainty/change_log` 齐全、`limitations` 如实
- [ ] `validate_plan.py` 退出码 0 或仅警告；`main.py check` 退出码 0 或仅警告（警告已说明）
