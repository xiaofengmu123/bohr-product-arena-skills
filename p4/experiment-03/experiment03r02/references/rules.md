# 规则与检查清单：从材料到可执行参数方案

本文是 `SKILL.md` 第 4 节执行流程的细则，用于指导 Agent 在每一阶段判断"该写什么、依据是什么、
哪里可能出错"。所有规则以"可复核"为第一优先级：每条结论都要能指回材料的逐字片段（locator + quote）。

## 1. 关键参数识别与可行域约束

### 1.1 识别规则

- 参数必须来自材料原文，不依据领域标签臆测：先读设备手册（量程/精度/步进）、材料规格（耐温/压力/兼容性）、
  安全阈值（闪点/毒性/压力上限）、历史记录（已试过的点与响应）。
- 每个参数只记"本任务真实约束"：温度、时间、摩尔比、投料量、转速、压力等；泛泛的经验值不算。
- 互斥关系（如 A 升高时 B 必须降低）写成参数间的耦合约束，写入 `risks` 或参数 `notes`，不隐藏。

### 1.2 可行域规则（对应评分"建议参数落在真实可行域内"）

- 每个参数必须有：名称、单位、建议值 `value`、可行区间 `[min, max]`、步进 `step`。
- 硬门槛三类逐项核对：`device_limit`（设备量程）、`material_limit`（材料耐温/限制）、
  `safety_limit`（安全阈值）。建议值与目标值任何一项越界都是阻断错误。
- `step` 必须是设备能实际设定的粒度（如 5 °C、0.1 mol 比），不得虚设。
- 目标温度与材料耐温冲突（如目标 200 °C、材料耐温 150 °C）属于**约束冲突**：写入 risks，
  明确"降目标 / 换材料 / 转人工"三种处置，不得悄悄把材料耐温改成 200 °C。

### 1.3 核查清单

- [ ] 每个参数的 min/max/step 有出处（locator + quote）
- [ ] value 落在 [min, max]，且不越三类硬阈值
- [ ] 互斥/耦合约束已显式记录
- [ ] 没有把"领域常识"当成本任务约束

## 2. 响应指标定义与代理建模

### 2.1 口径规则（对应评分"响应指标口径与验证方式"）

每个响应指标必须写全：`id`、`name`、`unit`、`measurement_method`（怎么测）、
`direction`（max / min / target）、`target`（目标值）、`acceptable_lower`（可接受下限，
或 `acceptable_upper`）。口径要能在实验室原样执行，如"GC 面积归一法，单位 %，取三次均值"。

### 2.2 预测方式与不确定度

- 只能三选一并写明：`historical_fit`（历史数据拟合）、`surrogate`（代理模型）、
  `empirical_rule`（经验规则）。预测值与实测必须区分：预测值写 `predicted_value`，
  实测值缺数据时写 `pending_human` 或 `not_reported`。
- 每个预测必须带 `prediction_uncertainty`（如 ±3%），并说明来源（残差/置信区间/经验偏差）。
- 两个来源对同一指标不一致时，两个都记录并标 `source_conflict`，不隐藏。

### 2.3 核查清单

- [ ] 每个指标的测量方法可执行（非"测一下"）
- [ ] direction / target / 可接受下限齐全
- [ ] 预测方式与不确定度已披露
- [ ] 冲突来源已双录并标 source_conflict

## 3. 搜索策略

### 3.1 选择规则

- 参数维度少（≤3）且定义域小：网格（grid）。
- 维度中等、每轮实验贵：序贯设计（sequential）。
- 维度高、响应有噪声、预算允许：贝叶斯优化（bayesian）。
- 参数多但可快速粗筛：分阶段筛选（staged_screening，先粗后精）。

### 3.2 可复现规则（对应评分"候选点产生过程可复核"）

- 写明 `initial_points`（初始点怎么选）、`per_round`（每轮补哪些点、如何用上一轮结果调整）、
  `stop_criteria`（收敛与停止判据，如"连续两轮最优响应差 < 1%"）。
- 候选点由 `scripts/main.py doe --seed 0` 生成，固定种子保证两次运行一致。
- 每轮评估结果（哪些点被保留/舍弃、为什么）写入 `candidate_evaluation` 或 `procedures`。

### 3.3 核查清单

- [ ] method 与参数维度/预算匹配
- [ ] 初始点、每轮补点、停止判据三要素齐全
- [ ] doe 可复现（同种子同结果）
- [ ] 取舍理由可追溯（记录在案，非口头）

## 4. 实验成本与时间预算的权衡

### 4.1 口径规则（对应评分"成本与单位口径自洽"）

- 成本明细逐条：`name`、`quantity`、`unit`、`unit_price`、`subtotal`；
  满足 `subtotal = quantity × unit_price`、`total = Σsubtotal`。
- 单位口径统一（统一币种、统一时间单位），机时/耗材/样品数/通量分别列出。
- 时间预算：`time_hours`（预计耗时）与 `time_budget_hours`（上限），不越上限。

### 4.2 多目标取舍规则（对应评分"成本受限时牺牲多少可接受"）

- 每个取舍写一句可量化的代价，如"收率每提高 1%，机时增加约 0.5 h（80 元/h）"，
  写入 `cost_budget.tradeoff_note`。
- 明确"可接受的牺牲上限"：如"收率 ≥ 80% 时，为省 30% 成本可接受收率降 5%"，而非"尽量平衡"。
- 推荐方案 = 可行域内成本-响应联合权衡的最优，而非单指标最优。

### 4.3 核查清单

- [ ] subtotal/total 自洽（validate_plan 会复核）
- [ ] 单位口径统一
- [ ] tradeoff_note 给出可量化代价与牺牲上限
- [ ] 总成本 ≤ 预算上限（若设上限）

## 5. 风险与异常处理

必须逐项覆盖以下六类（对应评分"异常处理"）：

| 场景 | 检测 | 处置 |
|---|---|---|
| 无可行解 | 所有候选点越界/超预算 | 报告无可行解，放宽哪条约束需专家确认，status=partial/insufficient_evidence |
| 约束冲突 | 目标温度 > 材料耐温 | 降目标 / 换材料 / 转人工，三选一并记录 |
| 数据缺失 | 缺设备量程/历史记录 | 写入 uncertainty + limitations，不编造 |
| 设备报错 | 运行中设备异常 | 记录到 errors，给出重试/换设备/转人工 |
| 指标矛盾 | 两个响应指标方向冲突 | 双录并标 source_conflict，说明取舍 |
| 输入损坏 | 坏 JSON/坏编码 | 捕获到 errors/degradations，继续处理其余材料；全坏则 status=input_error |

## 6. 证据溯源（科研场景硬要求）

- 每个关键结论/数值/参数，都要能指回材料中的**逐字片段**：`locator`（如 `materials/paper.md#p3`、
  `input/plans.json#v1`）+ `quote`（原文逐字，不转述）。
- 不虚构引用、DOI、数值；缺失写 `pending_human` 或 `not_reported`。
- 候选方案是规划场景（prospective）：不得声称为实际实验室报价、供应商报价、安全审批或实测未来响应；
  价格/产能/响应预测一律标注"组织方给定"或"模型估计"。

## 7. 阶段预算自查（对应"900 秒 / 64 请求 / 早落盘"）

| 阶段 | 时间 | 请求上限 | 必须产出 |
|---|---|---|---|
| 0 骨架 | 0–3 分钟 | 6 | `/app/output/result.json`（partial）已落盘 |
| 1 参数/评估 | 3–8 分钟 | 24 | 参数可行域 + evaluate + doe |
| 2 成本/风险 | 8–13 分钟 | 24 | 成本预算 + 风险 + sources/uncertainty |
| 3 收尾 | 13–15 分钟 | 10 | finalize + check 通过 |

- 阶段 0 未完成不得进入阶段 1；时间/请求不足时，保留已落盘 result.json 即视为完成部分交付。
- 每次修改 plan.json 后重跑 `validate_plan.py`，阻断错误清零后再继续。
