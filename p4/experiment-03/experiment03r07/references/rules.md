# 规则与检查清单

本文件给出方案建模的判定规则与鲁棒性边界清单。它是 SKILL.md 的补充，供 Agent 在执行阶段对照，不替代实际读取材料。

## 1. 参数识别规则

- 只把“影响可测量响应且定义域有限”的量列为关键参数；参数名、单位、量程必须与任务中的设备/材料对得上。
- 每个参数必须抽出：建议值、可行区间（min/max）、步进、约束来源与逐字 quote。
- 可行区间由三类硬约束取交集：设备量程、材料耐温/耐压、安全阈值；历史数据只用于在可行域内选点，不用于放宽硬约束。
- 参数间互斥/联动关系（如压力-温度上限联合约束）写入 `risks` 或 `constraint_source`，不得忽略。
- 无法确定量程的参数不编造取值；写 `unverified_values` 并降级。

## 2. 响应指标口径规则

- 每个指标写全：名称、单位、测量方法/仪器、方向（max/min/target）、目标值、可接受下限、预测方式、预测不确定度。
- 预测方式三选一并如实披露：历史数据拟合（给拟合范围与样本数）、代理模型（给模型形式与训练依据）、经验规则（给规则来源）。
- 同一指标多来源不一致时，两条都记录并标 `source_conflict`，最终取舍写理由。

## 3. 搜索策略规则

- 在网格、序贯设计、贝叶斯优化、分阶段筛选之间择一，写明：初始点怎么选、每轮补哪些点、如何利用上一轮结果、收敛/停止判据。
- 候选点必须可由 `scripts/main.py doe --seed 0` 确定性复现；改种子会改变随机分量，因此正式记录用固定 seed。
- 停止判据至少含一条量化的（如响应改善 <ε 或预算耗尽）与一条安全的（如触及硬约束即停）。

## 4. 成本与时间权衡规则

- 把机时、耗材、样品数、通量都纳入 `cost_budget.items`，每项给数量、单价、小计与依据。
- `tradeoff_note` 必须写“成本受限时牺牲多少响应指标可接受”，例如：单位成本增加 20% 以内可接受，超出则接受响应目标下调 x%。
- 成本口径与单位必须自洽（元/机时/小时），不要混用“预算”与“报价”。

## 5. 风险与异常处置规则

至少覆盖六类并给处置（降级/转人工/终止）：

1. 无可行解（可行域为空）
2. 约束冲突（如目标温度 > 材料耐温）
3. 数据缺失
4. 设备报错/故障
5. 指标互相矛盾
6. 权限不足/设备不可用

处置必须是可执行动作，不是“注意风险”的泛化表述。

## 6. 鲁棒性边界清单（本变体重点）

脚本与流程必须满足：

| 场景 | 要求 |
|---|---|
| 空输入目录 | 退出码 0，写合法 result.json（`insufficient_evidence`），不抛异常 |
| 坏 JSON / 坏编码 | 捕获并记录到 `errors`/`degradations`，继续处理其余材料 |
| 缺参数/未知参数 | `--input/--output/--work` 缺省指向 `/input`、`/app/output`、`/app/work` |
| 单文件 > 2MB | 跳过并记录 `skipped:too_large`，不崩溃 |
| 写盘失败 | 降级到最小合法产物，记录 `errors`，不崩溃 |
| 重复运行 | 同一输入两次运行结果一致（固定 seed、确定性布局） |
| 非数值参数 | validate/doe 只做可判定检查，非数值标记为警告而非崩溃 |

## 7. 诚实性规则（硬性）

- 不编造：评测分数、运行结果、科学数据、来源、DOI、文件路径一律不得伪造。
- `status` 如实：材料不足就 `insufficient_evidence`，不填充示例冒充结果。
- 未确认的安全/伦理/设备可用性/专家事项写入 `pending_human`，不写成已确认事实。
- 交付前在本机独立环境跑 `scripts/selftest.py`，退出码必须为 0。
