# 规则与清单：从材料到可执行参数方案

本文是执行 `SKILL.md` 阶段 B–C 时的判定规则，供 Agent 与复核人共同使用。目标不是写得长，而是每一步都有可判定的出口。

## 1. 关键参数识别规则

1. 只把「可操作、有量纲、对至少一个响应指标有方向性影响」的量列为关键参数；温度、时间、浓度、配比、压力、转速等优先于泛化描述。
2. 每个参数必须能从材料中定位约束来源，并给出逐字 quote：
   - 设备量程 → `bounds_origin=device_range`
   - 材料耐温/耐压 → `material_limit`
   - 安全阈值（如爆炸极限、毒理限值）→ `safety_threshold`
   - 历史实验 → `historical`
   - 专家经验 → `expert`（此类最弱，必须标注 pending_human）
3. 可行区间 = 所有约束的交集；交集为空 → 无可行解，按异常处置，不悄悄放宽约束。
4. 步进取「测量精度、控制精度、成本可分辨度」三者中较粗者；步进必须能整除可行区间或有明确取整说明。
5. 互斥/耦合写进 `interactions`：例如「温度 × 时间共用机时预算」「A/B 配比和为 1」。

## 2. 响应指标口径规则

1. 一条响应指标必须写清：**口径**（分子/分母如何定义）、**单位**、**测量方法**（含仪器与样品处理）、**方向**、**目标值**、**可接受下限/上限**、**测量不确定度**。
2. 预测必须声明方法：`historical_fit`（历史数据拟合，给拟合函数与样本量）、`surrogate`（代理模型，给模型类型与训练数据）、`empirical_rule`（经验规则，给规则出处与适用范围）、`none`（无法预测，明确写 pending_human）。
3. 预测不确定度必须落到量纲：如「转化率 ±3%（绝对）」或「95% 置信区间 [88, 96]%」，禁止只写「有一定误差」。
4. 指标与参数的关系判断要成立：写清单调/峰值/交互，并指向依据（source id）。

## 3. 搜索策略规则

1. 先声明方法（网格/序贯/贝叶斯/分阶段筛选）并说明为什么选它：维度数、预算、是否允许批实验、有无历史代理。
2. 初始点：优先放可行域中心、历史最优邻域、约束边界附近各一；每个初始点写理由。
3. 每轮补点：写明根据上一轮结果补在哪里（如沿最优方向加密、在不确定度最大处补点）。
4. 停止判据至少两条：预算耗尽（硬停）+ 收敛（响应变化 ≤ 阈值 或 不确定度 ≤ 阈值）。停止后写明停在哪个候选点。
5. 候选点必须可由 `python scripts/main.py doe --seed 0` 复现；同一输入不得出现不同候选点。

## 4. 成本与时间权衡规则

1. `cost_budget.items` 每项给 `amount × unit` 与 `rate`（单价）或 `cost`（小计），总量口径自洽，不混用单位。
2. 必须写 `tradeoff_note`：例如「机时减半时，接受转化率从 95% 降到 88%，因该区间仍在可接受下限之上」。
3. 多目标冲突时写明取舍顺序（先保证安全边界，再响应，再成本），并给出量化折中点。

## 5. 风险与异常处置清单

| 场景 | 识别信号 | 处置 |
|-|-|-|
| 无可行解 | 可行区间为空 | 写 `exception_handling`，降级（换材料/降目标）或转人工；status 不写 ok |
| 约束冲突 | 目标温度 > 材料耐温 | 记录双方 quote，标 `source_conflict`，不得悄悄改约束 |
| 数据缺失 | 约束/响应无来源 | 写入 `uncertainty.missing_data` 与 `limitations`，标 pending_human |
| 设备报错 | 运行期工具失败 | 记 `errors`/`degradations`，用其余材料继续；全部失败转 input_error |
| 指标矛盾 | 两来源同一指标不一致 | 两个都记录，标 `source_conflict`，选保守值并说明 |

## 6. 证据溯源清单

- 每个关键数值/约束/响应口径必须回填 `sources[]`，含 `locator` + 逐字 `quote`。
- `supports` 指向具体字段路径，保证「结论 → 证据」可逆查。
- 不虚构 DOI、URL、页码、数值；缺失写 `not_reported` 或 `pending_human`。
- 材料与领域标签冲突时，以实际材料内容为准。

## 7. 交付前 30 秒自检

1. `python scripts/selftest.py` 退出码 0。
2. `python scripts/validate.py result --result /app/output/result.json --output-dir /app/output` 退出码 0 或 2。
3. `result.json` 中 change_log 首条为骨架落盘，status 如实。
4. 打开 `/app/output/plan.md`，确认实验人员能据其开机或明确知道缺什么。
