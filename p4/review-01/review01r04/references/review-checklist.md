# 六类分面检查清单与判据

本清单是 `main.py` 中 `ANCHORS` 的语义定义，Agent 逐锚点排查，每条 finding 用
`check_anchor` 回到本表。六面分别为：事实核验 `fact_check`、引用支持
`citation_support`、方法设计 `method_design`、统计报告 `statistics_report`、
论证链 `argument_chain`、学术规范 `academic_norms`。

## 1. 事实核验（fact_check）

- **FCT-1 数值一致性**：摘要 / 正文 / 图表 / 表格中的同一数值是否一致（样本量、
  比例、效应量、时间、单位、成本等）。冲突时两处都记录并标 `source_conflict`，
  不擅自取舍。
- **FCT-2 术语与定义一致性**：同一术语前后是否同义、缩写是否首现定义、单位体系
  是否统一。
- **FCT-3 可核验断言**：正文可被外部事实核验的断言（日期、事件、机构、公认数据）
  是否有据；无法核验则标 `to_review`，不臆断。
- **FCT-4 与已确立常识/文献一致性**：是否与公认事实冲突；仅当有明确依据时判定，
  学科惯例差异不判缺陷。

## 2. 引用支持（citation_support）

- **CIT-1 引用存在性**：正文标注 ↔ 参考文献条目是否一一对应，是否存在孤标或孤条。
- **CIT-2 引用主张匹配**：本文论断与被引文献主张是否对应。**必须同时给出本文
  论断 quote 与被引文献主张**（能读到则给原文，读不到则标 `unverifiable`）。
- **CIT-3 引用数据可复核**：被引数据 / DOI / 页码是否足以追溯；缺失写
  `pending_human`，不臆断被引文献主张。
- **CIT-4 引用范围外推**：引用是否只支持部分论断却被用来支持更强结论。

## 3. 方法设计（method_design）

- **MET-1 对照设置**：是否有对照、对照是否足以回答研究问题；缺对照时说明为何
  不设对照可接受，否则记缺陷。
- **MET-2 样本量与抽样方式**：样本量依据、抽样 / 纳入排除、代表性说明是否齐全。
- **MET-3 评价指标选择与定义**：指标是否合适、是否给出定义与计算口径。
- **MET-4 重复与随机化**：实验重复、随机化、盲法、批间控制是否说明。
- **MET-5 缺陷 vs 报告不全**：区分"方法本身有缺陷"与"方法可接受但报告不全"，
  前者 `critical/major`，后者 `minor` 或 `standards_issue`。

## 4. 统计报告（statistics_report）

- **STA-1 显著性报告**：p 值 / 检验量 / 自由度 / 检验名称是否报告完整。
- **STA-2 误差与置信区间**：误差、置信区间、离散度量是否缺失。
- **STA-3 效应量与样本量依据**：是否只报显著性而缺效应量或功效分析。
- **STA-4 多重比较校正**：多次比较是否校正；未校正是否说明。
- **STA-5 分布与检验前提**：数据分布、方差齐性等前提是否检查或说明。

## 5. 论证链（argument_chain）

- **ARG-1 假设→结论路径完整性**：从假设到结论的推理是否连续可追溯。
- **ARG-2 缺失环节 / 跳跃**：定位前提与结论之间缺掉的步骤。
- **ARG-3 循环论证**：结论是否已被前提预设。
- **ARG-4 因果 vs 相关**：相关结果是否被表述为因果；混淆变量是否讨论。
- **ARG-5 结论外推范围**：结论是否超出样本、条件或数据支持范围。

## 6. 学术规范（academic_norms）

- **NOR-1 数据可用性声明**：数据 / 代码 / 材料可用性声明是否缺失。
- **NOR-2 伦理与利益冲突声明**：人类 / 动物伦理、同意、利益冲突、资助是否声明。
- **NOR-3 图表版权与来源**：图表是否注明来源 / 版权 / 许可。
- **NOR-4 术语与格式规范**：术语、缩写、单位、引用格式是否符合目标期刊要求。
- **NOR-5 实质问题 vs 规范问题**：把影响结论的实质问题与纯格式问题分开呈现。

## 严重度判据

- `critical`：实质错误导致核心结论不可靠或误导（事实错误、数据矛盾、引用错配
  支持核心结论、统计方法错误、逻辑断裂使结论不成立、学术不端）。
- `major`：影响判断但可修正（关键子结论证据不足、缺关键对照或样本量、关键统计
  量缺失、论证缺一环）。
- `minor`：局部问题（个别术语不一致、报告不全但不影响主结论、声明 / 格式缺失）。
- `suggestion`：改进建议而非缺陷（补充稳健性分析、可读性、透明度）。

## 问题性质（issue_type）

- `factual_error`：事实 / 数值 / 术语错误（仅当 `verdict=confirmed` 且有明确依据）。
- `insufficient_evidence`：证据不足（缺引用、缺样本量、缺统计量、缺对照）。
- `standards_issue`：规范问题（声明缺失、格式、伦理 / 利益冲突 / 数据可用性）。
- `suggestion`：建议性意见，非缺陷。

## 误报抑制规则（必读）

1. **不把学科写作惯例、期刊格式差异、作者的有意取舍判为缺陷**，除非与明确规范
   冲突且能给出依据。
2. 同一问题只列一次；同一段内的多个表现合并为一条，避免刷条。
3. 引用无法核验时写 `to_review` + `insufficient_evidence`，**不臆断被引文献主张**。
4. 图表 / 图片读不到时**不猜数值**，写进 `pending_human` / `unchecked_items`。
5. 原文歧义或两处数值冲突时两处都记录并标 `source_conflict`，不擅自取舍。
6. `quote` 必须逐字命中（白空格归一；跨行可、跨段不可），`check` 未 PASS 不得
   `build` 为 `confirmed`。
7. 无法确认的条目一律 `to_review`，不凭空补结论；材料不足就降级，不编造数据。
