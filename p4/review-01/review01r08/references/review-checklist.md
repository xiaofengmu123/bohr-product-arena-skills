# 六类审查检查清单与判据

本文件是 `scripts/main.py` 的语义补充：脚本负责定位、逐字命中与字段校验，这里负责
“什么时候该标严重、该标什么性质、哪些情况不该报”。审查时逐面使用，凡判断为问题必须
能指回原文（`location` + 逐字 `quote`），否则不成立。

## 1. 六类 facet 检查锚点

| facet | 查什么 | 典型缺陷 | 落点 |
|---|---|---|---|
| `fact_check` | 数值/事实是否前后一致、是否与公认事实冲突 | 摘要写“治愈”正文写“有效”；数值在摘要/正文/图表不一致 | 记录两处原文 |
| `citation_support` | 正文论断与被引文献主张是否对应 | 引用 A 却表述为 B 的主张；断言“已证实”但被引文献只是综述 | 列本文论断 + 被引文献主张的对应关系 |
| `method_design` | 对照、样本量、抽样、指标选择、重复与随机化 | 无对照；样本量无依据；指标与目标不匹配 | 区分“方法有缺陷”与“报告不全” |
| `statistics_report` | 显著性、效应量、误差、置信区间、检验方法 | 只写“显著”不给 p 值；有 CI 无样本量；误差棒无说明 | 指出缺哪个量 |
| `argument_chain` | 假设→证据→结论的推理路径 | 相关当因果；结论外推超出样本；循环论证 | 定位断点在哪一步 |
| `academic_norms` | 数据可用性、伦理、利益冲突、图表版权、术语格式 | 缺 DAS；临床研究无伦理声明；图片无来源 | 规范问题与实质问题分开 |

## 2. 严重度判据（severity）

| 级别 | 判据 | 示例 |
|---|---|---|
| `critical` | 结论不成立、数据不可信、存在学术不端，必须撤稿/拒稿 | 关键结论与数据直接矛盾；伪造数据迹象 |
| `major` | 影响结论可信度，需大改才能发表 | 无对照；关键统计缺失；引用错配支撑核心论断 |
| `minor` | 局部可修复，不影响主要结论 | 术语前后不一；个别格式不合规 |
| `suggestion` | 可读性/稳健性改进，非缺陷 | 建议补充敏感性分析；建议换更精确措辞 |

判据优先级：先判断是否改变结论，再判断修复成本。拿不准时降一级并标 `to_review`。

## 3. 问题性质判据（issue_type）

| 性质 | 含义 | 判据 |
|---|---|---|
| `factual_error` | 陈述与原文事实/公认事实冲突 | 能找到冲突的两处证据 |
| `insufficient_evidence` | 论断缺少可核验支撑，或材料不足以判断 | 缺对照/样本量/统计量/被引文献无法核验 |
| `standards_issue` | 违反期刊/领域/伦理规范 | 缺声明、格式不合规、术语不统一 |
| `suggestion` | 非缺陷的建议性意见 | 提升稳健性/可读性 |

## 4. 误报抑制规则（先排除，再上报）

1. 学科写作惯例（如“本研究发现”措辞、主动/被动语态）不是缺陷。
2. 期刊格式差异（参考文献样式、章节命名习惯）只在明确目标期刊要求时才报 `standards_issue`，否则降为 `suggestion` 或不上报。
3. 作者的有意取舍（如回顾性研究不用 RCT 对照）只在未说明理由且影响结论时上报。
4. 无法核验 ≠ 错误：参考文献缺失时列 `unchecked_items`，不臆断被引文献主张。
5. 同一问题的多个表现合并为一条 finding，避免重复计数。
6. 主观判断必须写“可接受范围 + 不确定性”，并把结论标 `to_review` 而非 `confirmed`。

## 5. quote 与 locator 规范

- `quote` 是原文逐字片段，可跨行但**不跨段**；禁止改写、补字、删字。
- `location` 用 `show` 输出的 locator：纯文本 `para{n}`，PDF 页内 `p{page}#para{n}`。
- 每个关键结论至少一条 `evidence`（`source_id` + `locator` + 逐字 `quote`）。
- 数值冲突时两处都记录并写进 `uncertainty`，不擅自取舍。
- 脚本 `check` 会逐字命中 quote 并校验 location 指向的段落是否含该 quote；FAIL 就回原文重抄。

## 6. 完成标准（对应结果完整性）

六类 facet 中，与本文相关的每一面都必须**有 finding 或列入 `unchecked_items`**（说明不适用/
待复核原因）。全部未覆盖时 `status` 不得为 `ok`。
