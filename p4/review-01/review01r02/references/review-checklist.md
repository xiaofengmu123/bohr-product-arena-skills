# 六类分面审查清单与判定口径

本清单是 Agent 在 `facet_audit` 阶段逐条排查的锚点，也是 `check` 校验 severity /
issue_type / verdict 是否与判据一致的依据。判定只以材料逐字片段为准：每一条 finding
必须能指回原文 locator + quote，没有原文依据就不写 finding，改列 `unchecked_items`。

## 1. 六个分面与检查锚点

| facet | 中文 | 重点检查 |
|---|---|---|
| `fact_check` | 事实核验 | 数值在摘要/正文/图表间是否一致；术语与定义前后是否统一；结论是否与数据吻合；是否存在笔误、张冠李戴、来源冲突 |
| `citation_support` | 引用支持 | 正文论断与被引文献主张是否对应；引文是否真的支持所引内容；参考文献是否可定位；是否漏引或错配引文 |
| `method_design` | 方法设计 | 对照设置、样本量与抽样方式、评价指标选择、重复与随机化说明；区分“方法本身有缺陷”与“方法可接受但报告不全” |
| `statistics_report` | 统计报告 | 显著性报告、效应量与置信区间、误差与精度、检验方法、多重比较校正；是否“有 p 值无效应量”等 |
| `argument_chain` | 论证链 | 从假设到结论的推理路径是否完整；是否有缺失环节、循环论证、因果与相关混淆、结论超出数据范围的外推 |
| `academic_norms` | 学术规范 | 数据可用性声明、伦理与利益冲突声明、图表版权与来源、术语与格式是否符合目标期刊；规范问题与实质问题分开呈现 |

一个分面只要与本稿相关，就必须有 finding（发现问题）或显式说明“已查未发现问题”；
查不到或材料不足，就写进 `unchecked_items` 并在 `coverage` 标注 `not_checked`，不得
凭空补结论。

## 2. severity 判据

| severity | 含义 | 触发条件（示例） |
|---|---|---|
| `critical` | 致命 | 结论与数据直接矛盾、引用伪造或张冠李戴、统计结果误读导致结论反转、伦理/数据造假迹象 |
| `major` | 主要 | 方法缺对照/样本量不足且未说明、缺失关键统计量、论证链关键环节断裂、数值在关键处冲突 |
| `minor` | 次要 | 局部不一致、报告不全但可补、术语不统一、图表标注缺失，不影响主结论 |
| `suggestion` | 建议 | 可改进项、格式/表述问题、补充说明建议，不构成实质缺陷 |

severity 依据的是问题对结论成立性的影响，不是出现次数；同一条问题的多条证据并入一条
finding，不重复列。

## 3. issue_type 判据

| issue_type | 含义 | 何时使用 |
|---|---|---|
| `factual_error` | 事实错误 | 有逐字原文证明数值/事实/引用错误或来源冲突 |
| `insufficient_evidence` | 证据不足 | 缺少对照、样本量、统计量、引文等支持，无法据现有材料确认结论 |
| `standards_issue` | 规范问题 | 伦理/利益冲突/数据可用性/版权/格式等规范缺失或不合规 |
| `suggestion` | 建议性意见 | 不属错误、只是可改进 |

区分要点：`factual_error` 要求能定位“错在哪里”；只有“缺少某物”而没有“错值”时用
`insufficient_evidence`；纯格式用 `standards_issue`。

## 4. verdict 判据

| verdict | 含义 | 何时使用 |
|---|---|---|
| `confirmed` | 已确认 | 原文逐字可证、判定与学科常识/写作规范一致，无其他合理解释 |
| `to_review` | 待复核 | 证据存在但存在歧义、作者有意取舍、跨处冲突孰对孰错未知、或需结合外部文献核验 |
| `not_checked` | 未检查 | 仅用于骨架/未审计项，不作为正式 finding 的 verdict |

原则：无法确认一律 `to_review`，不擅自升级为 `confirmed`；冲突信息两个来源都记录并标
`source_conflict`，写入 `uncertainty`，不擅自取舍。

## 5. 误报抑制规则（关键，逐条遵守）

1. **不把学科写作惯例当缺陷**：被动语态、作者署名顺序、分节习惯差异不是问题。
2. **不把期刊格式差异当缺陷**：参考文献样式（数字制 vs 作者-年份制）、图表位置差异，
   只在不一致到影响可复核时才列，且用 `standards_issue` + `suggestion`。
3. **不把作者有意取舍当缺陷**：样本量小但已说明局限并讨论，属于作者判断，不判为错误；
   除非未说明且影响结论。
4. **不臆断被引文献主张**：看不到被引文献全文时，不写“该文献不支持此论断”，改列
   `citation_support` 为 `unchecked_items`，注明“无法核验”。
5. **机械预审线索需人工确认**：`mechanical=true` 的 finding 默认 `to_review` + 低
   置信度，Agent 复核后才能在 `draft.json` 里改 verdict/severity/置信度。
6. **同义重复不重复列**：同一问题只列一条，位置给最关键的 locator，其余位置放 evidence。

## 6. coverage 标注规则

`draft.json.coverage` 是 Agent 对“该分面是否已完成审计”的显式声明，六类分面各取：

- `checked`：已逐项审完，有 finding 或确认无问题；
- `n/a`：该分面与本稿体裁无关（如纯观点文无统计，写清理由到 `unchecked_items`）；
- `not_checked`：尚未审完或材料不足。

机械预审产出的 finding **不**自动把分面标记为 `checked`；只有 Agent 实际复核后才改。
