# 论文质量审查检查清单（六类审查面）

本文件是 `main.py check` 校验之外的人工判据：Agent 在 `draft.json` 中落笔前逐条对照。
每个检查项给编号（如 `FC-1`），finding 的 `rationale` 应引用该编号，使判定可追溯。

## 1. 事实核验（fact_check）

| 编号 | 检查锚点 | 常见缺陷 |
|-|-|-|
| FC-1 | 摘要 / 正文 / 图表 / 结论中的同一数值是否一致 | 同一指标多处数值冲突 |
| FC-2 | 关键数值是否有来源（实验、文献、数据声明） | 数值无出处、口径不明 |
| FC-3 | 术语与定义全文是否统一 | 同名异义、前后定义漂移 |
| FC-4 | 结论数字是否超出图表/正文所示范围 | 外推、四舍五入失真 |

- 判定标准：数值冲突用 `source_conflict` 记录双方 locator+quote，不擅自取舍；`verdict=confirmed` 仅当双方原文都已核对。
- 误报抑制：作者明确声明的口径差异（如"未报告 p 值"）不判为冲突；期刊数字格式差异不判错。

## 2. 引用支持（citation_support）

| 编号 | 检查锚点 | 常见缺陷 |
|-|-|-|
| CS-1 | 正文论断与被引文献主张是否对应 | 引文不支持所引内容、张冠李戴 |
| CS-2 | 被引文献是否真实存在且字段齐全 | 编号缺失、作者/年份/DOI 不完整 |
| CS-3 | 引用位置是否紧跟被支持论断 | 堆叠引用、支持对象不清 |

- 判定标准：每条该类 finding 的 `evidence` 必须含 `supporting_citation` 证据项，逐条写"本文论断 quote"与"被引文献主张 quote"的对照，`relation` 取 `supports/contradicts/unverifiable/not_found`。
- 无法核验被引文献全文时：`verdict=to_review`，写入 `unchecked_items` 并注明"无法核验"，不臆断被引文献主张。

## 3. 方法设计（method_design）

| 编号 | 检查锚点 | 常见缺陷 |
|-|-|-|
| MD-1 | 对照设置是否足够（基线/空白/阳性对照） | 无对照、对照不足 |
| MD-2 | 样本量与抽样方式是否说明 | 样本量缺失、抽样偏倚 |
| MD-3 | 评价指标是否合理并适配任务 | 指标单一、指标与目标不匹配 |
| MD-4 | 重复与随机化是否说明 | 未说明重复次数/随机种子 |
| MD-5 | 是否区分"方法本身有缺陷"与"方法可接受但报告不全" | 两类混为一谈 |

- 判定标准：`issue_type=factual_error` 只用于方法本身明显不合理；报告不全用 `insufficient_evidence`；改进性意见用 `suggestion`。

## 4. 统计报告（statistics_report）

| 编号 | 检查锚点 | 常见缺陷 |
|-|-|-|
| SR-1 | 显著性/误差/置信区间是否报告 | 只有点估计、无不确定性 |
| SR-2 | 检验方法与多重比较校正是否说明 | 未报告所用检验、未校正 |
| SR-3 | 效应量是否报告 | 只给 p 值不给效应量 |
| SR-4 | 数据是否满足检验前提 | 前提未说明即下结论 |

- 误报抑制：学科惯例允许的简化（如探索性研究仅报告描述统计）不判为缺陷，但应写入 `uncertainty`。

## 5. 论证链（argument_chain）

| 编号 | 检查锚点 | 常见缺陷 |
|-|-|-|
| AC-1 | 假设 → 证据 → 结论的推理是否完整 | 缺失中间环节 |
| AC-2 | 是否存在循环论证 | 结论作为前提 |
| AC-3 | 相关与因果是否混淆 | 观察性数据推断因果 |
| AC-4 | 结论外推是否超出数据范围 | 单数据集/单场景推广至全部 |

- 判定标准：每条定位"断点"原文 + 前一步/后一步的逐字 quote；`location` 用断点所在段。

## 6. 学术规范与可发表性（academic_norms）

| 编号 | 检查锚点 | 常见缺陷 |
|-|-|-|
| AN-1 | 数据可用性声明 | 缺失 |
| AN-2 | 伦理与利益冲突声明 | 缺失（涉及人体/动物/资金时） |
| AN-3 | 图表版权与来源标注 | 未标注来源/自绘未声明 |
| AN-4 | 术语与格式是否符合目标期刊 | 与期刊要求不符 |

- 判定标准：规范问题（格式、声明缺失）与实质问题（事实、方法、统计、逻辑错误）分开呈现，规范问题不混入 `factual_error`。

## 严重度判据（全六类通用）

| severity | 触发条件（示例） |
|-|-|
| critical | 结论依赖错误数值；引用完全不支持核心论断；方法缺关键对照且结论依赖它；统计缺失导致结论不成立 |
| major | 重要数值/引用存疑但可补；方法报告不全且影响可复现；规范声明缺失 |
| minor | 局部表述不一致、格式或术语不统一，不影响主结论 |
| suggestion | 可接受但可改进的写法、报告补充建议 |

`issue_type` 与 severity 解耦：`factual_error / insufficient_evidence / standards_issue / suggestion` 描述"是什么性质的问题"，severity 描述"影响有多大"。

## 误报抑制总则

1. 学科写作惯例、期刊格式差异、作者有意取舍 → 不判为缺陷，必要时写 `suggestion`。
2. 无法回到原文逐字定位的怀疑 → 不写 finding，写入 `unchecked_items`。
3. 主观判断 → 写明可接受范围与不确定性，`verdict=to_review`，不写 `confirmed`。
4. 同一问题不重复报：优先归入最相关的一个 facet，其他 facet 在 `rationale` 交叉引用。
