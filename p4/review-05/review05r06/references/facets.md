# 判定规则与检查项清单（facets）

本文档定义裁决口径。脚本 `extract.py` 只产出**候选观察**（observation），不判定问题；本清单约束 Agent 把观察逐条裁决为"成立（finding）/ 排除（dismissed）/ 待复核（pending）"，并控制误报与漏报。

## 1. 结论类型（finding.type）

| 类型 | 含义 | 必要条件 |
|---|---|---|
| `fact_error` | 可核对的客观错误（数值、单位、公式、元数据、张冠李戴） | 有原文反例或权威来源，能指出错在哪 |
| `insufficient_evidence` | 论断超出材料可支持的范围 | 指出论断 vs. 证据的缺口，不臆断对方造假 |
| `norm_violation` | 违反明确规范/指南/授权范围（引用、隐私、版权、伦理、投稿） | basis 写出条款/指南版本与原文 |
| `suggestion` | 不构成违规，但可改进（可读性、报告完整度） | 明确标注为建议，不升格为违规 |

## 2. 严重度（finding.severity）

- `critical`：可直接导致撤稿、伦理事故、法务风险，或核心结论被推翻。
- `major`：影响可复核性/合规性，须在提交前修正。
- `minor`：格式不一致、表述不严谨等局部问题。
- `info`：背景性说明，无违规。

分级依据要写进 `evidence`；同一事实不得因措辞差异升级。

## 3. 检查面与证据要求

每个 facet 都需给出"已查/待复核/未查"结论，不允许只挑最容易的一项。以下为默认覆盖底线；若 `case.json`/`task.md` 声明了具体审查面（`declared_facets`），以其为准并映射到这些 facet。

| facet | 检查项 | 最低证据要求 |
|---|---|---|
| academic_integrity 学术诚信 | 数据/图像复用、重复发表、不当署名、利益冲突、基金致谢一致性 | 定位具体段落/图注；注明疑似复用或冲突的证据 |
| citation 引用规范 | 正文引用 vs. 参考文献表一一对应、元数据与原文一致、引而不证、格式不统一 | 给出正文位置与参考文献条目号；外部存在性核验不可得时标 `pending_human` |
| privacy 隐私与数据合规 | 可识别个人信息、受限数据、未公开数据、脱敏/授权依据 | 只标注位置与类型，不复述敏感内容 |
| copyright 版权与许可 | 图/表/代码/数据集的来源标注、许可类型、复用条件 | 给出图注/来源位置；许可缺失即依据 |
| ethics 伦理审查 | 知情同意、伦理批件号与适用范围、动物规范、风险获益表述 | 给出声明位置；缺失且材料涉及人/动物研究时成立 |
| submission 投稿要求 | 按目标期刊/会议指南逐条映射：缺失、超限、格式冲突 | 写出指南名称、版本与日期；无指南时标 `pending_human` |
| quality 通用质量 | 结构完整性、缩略语首次定义、标题/摘要一致性 | 定位具体位置，不把风格差异当问题 |
| fact 事实核查 | 数值/单位/年份/指标的自洽性 | 只报可核对的反例；材料内无法核对则 `insufficient_evidence` |
| method 方法完整性 | 样本量、重复、实验设计、可复现要素 | 指出缺失项及其对可复核性的影响 |
| statistics 统计报告 | p 值、置信区间、效应量、检验名、校正 | 定位具体统计陈述；不自行重算 |
| logic 逻辑与论证链 | 结论与证据匹配、因果表述、以偏概全、过度推断 | 引用连接词与结论句，指出论证缺口 |

## 4. 误报抑制协议（每条观察必须裁决）

对 `evidence.json` 中的每个候选观察（尤其被触发器命中的），逐一裁决并留档：

1. **成立** → 写入 `findings.json` 的 `findings[]`，四要素齐全。
2. **排除** → 写入 `dismissed[]`，`reason` 写清"风格差异/学科惯例/表述差异/证据不足"等具体理由。
3. **待复核** → 写入 `pending[]`，`reason` 写清缺什么证据。

以下情形默认**不成立**，不得列为问题：个人写作风格、学科惯用表述、图表美观偏好、未超出材料声明的合理简化。

## 5. 引用一致性内部核查（材料内即可完成）

- 正文每个数字引用 `[n]` 是否能在参考文献表中找到对应条目；反过来查漏引。
- 作者-年份引用与参考文献表作者/年份是否一致（拼写、年份、et al. 使用）。
- 参考文献条目内部格式（作者、年份、期刊/卷/页、DOI）是否统一。
- **不**断言某条文献"真实/虚假存在"：除非运行环境提供检索工具且已核验，否则标 `pending_human` 并写"外部存在性未核验"。

## 6. 依据绑定（basis）

每条 finding 的 `basis` 必须写**可被独立核对**的出处：规范条款号（如 COPE、ICMJE 条款）、目标期刊指南的名称+版本+日期、数据授权范围原文，或材料内的明确矛盾位置。禁止编造条款号、期刊要求或文献元数据；拿不到出处就降级为 `insufficient_evidence` 或 `pending_human`，并说明缺什么。
