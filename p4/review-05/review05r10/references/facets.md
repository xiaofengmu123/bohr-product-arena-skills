# 检查面清单（六方向 + 通用质量）

以下为默认检查面（case.json 若声明 `review_facets`/`facets`/`checklist`，以声明为准）。
每个方向都必须给出"已查 / 待复核 / 未查"结论并写入 `report.coverage`；只挑最容易
的一条出报告会因"完整性"失分。每个方向列出**最低证据要求**——报问题时要能指出
原文位置与判定依据，报不出位置与依据的观察一律不升格为 finding。

## 1. 学术诚信（academic_integrity）
数据与图像复用、重复发表、不当署名、利益冲突声明缺失、致谢与基金信息不一致。
证据要求：指出复用/冲突的原文位置，或指出应声明而未声明的位置；依据来自规范条款
（如 ICMJE/COPE）或材料内部矛盾。

## 2. 引用规范（citation）
被引文献是否真实存在、元数据与原文是否一致、正文论断与所引文献是否一一对应，
识别引而不证、张冠李戴、格式不统一。
证据要求：给出正文论断位置 + 对应文献条目；DOI/作者-年份须来自检索到的原始记录，
未检索到标 `pending_human`，不得编造"该文献不存在/存在"。

## 3. 隐私与数据合规（privacy）
可识别个人信息、受限数据、未公开数据；是否有授权或伦理审批依据；脱敏与改写建议。
证据要求：只标位置与类型（姓名/ID/联系方式等），**不复述敏感内容**；判断"是否脱敏"
以材料自身是否声明为据。

## 4. 版权与许可（copyright）
图片、表格、代码、数据集等第三方材料的来源标注、许可类型、复用条件。
证据要求：指出具体图/表/代码位置 + 是否标来源与许可；判违规须有反证检查
（材料是否已写"经授权/CC BY/公共领域"）。

## 5. 伦理审查（ethics）
涉及人的研究是否说明知情同意、伦理批件编号与适用范围；动物实验规范；风险获益表述一致。
证据要求：指出应出现批件/同意声明的章节；"未报告"作为 `insufficient_evidence` 或
`norm_violation`（指南强制时），不可断言"未经伦理审批"。

## 6. 投稿要求（submission）
目标期刊/会议指南逐条映射：缺失项、超限项、格式冲突。
证据要求：依据目标期刊/会议指南的**具体版本与日期**；拿不到指南原文时标
`not_reported`/`pending_human`，不编造条目。

## 7. 质量（quality）
表述歧义、术语不一致、结构缺陷、明显笔误。多为 `suggestion`/`info`。

## 8. 统计（statistics）
p 值、样本量、效应量、区间估计、检验方法是否交代并自洽。
证据要求：指回数值位置；"未报告效应量"一般为 `suggestion`，除非材料声称了错误数值。

## 9. 方法（method）
样本、随机化、盲法、对照、可重复性是否交代充分。
证据要求：指出缺失要素的应出现位置；判定"证据不足"而非"方法错误"，除非材料自相矛盾。

## 10. 逻辑（logic）
论证链是否成立：前提-结论跳步、因果倒置、循环论证、以偏概全。
证据要求：给出前提句与结论句两处位置，说明断裂点；纯措辞差异不算逻辑错误。

## 11. 规范（norm）
以上未覆盖的其他规范/合规问题（作者单位、署名顺序、数据可用性声明等）。

## 覆盖矩阵写入方式

`findings.json` 的 `coverage` 形如：

```json
{
  "coverage": {
    "citation": {"status": "checked", "note": "核对 N 条引文，M 条可确认"},
    "ethics": {"status": "pending_review", "note": "伦理批件编号未在全文检索到，待确认"}
  }
}
```

`status ∈ {checked, pending_review, not_checked}`；`merge` 会自动汇总为
`checked_items / pending_review / not_checked` 三个桶。
