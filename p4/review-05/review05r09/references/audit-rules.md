# 审查判定规则（references/audit-rules.md）

本文件是判定依据，SKILL.md 的执行流程引用它。目标：每条问题"四要素齐备"——原文位置、判定依据、严重度、可执行修改建议；同时压制误报。

## 1. 类型四分类

| 类型 | 含义 | 典型情形 |
|---|---|---|
| `fact_error` | 事实错误 | 引用文献不存在、元数据与原文不一致、数值/单位/样本量与正文矛盾、张冠李戴 |
| `insufficient_evidence` | 证据不足 | 方法/统计/授权/伦理审批未交代且无法从材料补齐，论断缺少可核对出处 |
| `norm_violation` | 规范/合规问题 | 缺利益冲突声明、缺伦理批件号、第三方材料缺许可、可识别个人信息未脱敏 |
| `suggestion` | 建议性意见 | 可改进但不构成错误或违规，如格式统一、补充敏感性分析、增加重现性说明 |

判定纪律：把一条问题归为哪种类型，取决于**证据能支撑到什么程度**，而不是措辞轻重。证据不足时宁可降为 `insufficient_evidence`，不硬报 `fact_error`。

## 2. 严重度四级

| 严重度 | 触发条件 |
|---|---|
| `critical` | 影响结论可信度或存在实际合规风险：引用不实、数据矛盾导致结论不成立、缺伦理审批的涉人研究、未脱敏的受限数据 |
| `major` | 影响可复核性但结论仍可能成立：方法关键参数缺失、统计量不完整、许可来源不清、利益冲突缺失 |
| `minor` | 局部问题：单条引用格式不统一、个别图注缺来源、表述含糊 |
| `info` | 提示/建议，不影响结论：可选补充、风格提示、完善建议 |

同一问题同时可能触发多种类型时，取能成立且证据最稳的那一类；严重度只依据实际风险，不依据情绪。

## 3. 证据层级（evidence_tier）

- `verbatim`：直接引用原文逐字段落，quote 与源文件逐字一致（validate 可回查）。
- `inference`：由原文多处信息综合推出的结论，须在 `evidence` 中写明推理链。
- `external`：依据材料之外的可核对来源（期刊指南、许可条款、文献元数据），须在 `basis` 写明来源与版本/日期。

一条 finding 的 `quote` 必须来自被审材料本身；`basis` 可以引用外部规范，但要写清具体条款、版本、日期，不编造。

## 4. 判定流程：候选 → 证伪 → 结论

脚本产出的 `observations.json` 只是正则候选，不是结论。对每条候选执行**证伪**：

1. 回到 `locator` 所指位置读上下文（前后各 1–2 段）。
2. 判断候选是否是真实问题：是 → `confirmed`；证据不足以定 → `suspected` 并降低严重度；明确不成立 → `excluded`（不进入 findings）；需要人确认 → `pending_human`。
3. 每条 confirmed finding 补齐四要素与 `verdict/evidence_tier`。

## 5. 误报抑制（防止"大面积误报"）

以下情形**不得**判为问题，除非有具体证据：

- 风格差异：时态、语态、句长、学科惯用缩写。
- 学科惯例：本领域常见的实验描述顺序、术语选择、图表命名。
- 个人表述：无实质歧义的措辞偏好。
- 同一信息在两个位置表述一致但用词不同：不是矛盾。
- 引用编号格式的不同（方括号/上标/作者年份）：只在"同一文档内混用且目标指南要求统一"时记 `suggestion`，不是 `norm_violation`。

冲突信息处理：同一指标/数据在两个来源不一致时，**两条都记录**并标 `source_conflict`，不擅自判定哪条正确；无法确认的一律 `pending_human`。

## 6. 六方向逐项检查（覆盖完整性）

每个方向必须给出 `checked / pending_review / not_checked` 状态与备注，不允许只挑最容易的一条。

### 6.1 学术诚信（academic_integrity）
检查数据与图像复用、重复发表、不当署名、利益冲突声明缺失、致谢与基金信息不一致。
- 依据：材料中的作者贡献声明、基金号与致谢是否一致；图像/数据是否标注原创或来源；是否出现"已发表/已提交"表述而未说明。
- 判定要点：只有能指出"复用了什么、从哪里、是否越权"才算成立，否则只记观察。

### 6.2 引用规范（citation）
核对被引文献是否真实存在、元数据与原文一致、正文论断与所引文献一一对应。
- 检查正文每个 `[n]`/(Author, Year) 是否有对应条目；参考文献列表是否有正文未引的孤立条目；DOI/页码/年份是否自洽。
- 引而不证、张冠李戴、格式不统一分别归类；无法核对的文献标 `pending_human`，不直接判"文献不存在"（除非有可核对来源证明）。

### 6.3 隐私与数据合规（privacy）
识别可识别个人信息、受限数据、未公开数据；判断是否有授权或伦理审批依据。
- 识别 email、身份证号、电话、姓名、医院/机构名、患者/受试者编号等；已脱敏数据不算问题。
- 只标位置与类型，不复述敏感内容本身；拿不准标 `pending_human`。

### 6.4 版权与许可（copyright）
检查图片、表格、代码、数据集的来源标注、许可类型、复用条件。
- 查 "reproduced/adapted from/permission/©/license/CC BY/授权/转载" 等表述是否齐全；第三方材料是否给出许可类型与是否允许商用/改编。
- 缺来源 → `norm_violation` 或 `insufficient_evidence`（视是否可能补）。

### 6.5 伦理审查（ethics）
检查涉人研究是否说明知情同意、伦理批件号与适用范围；动物实验是否符合规范；风险获益表述与实际设计一致。
- 缺批件号但研究明显涉人/涉动物 → `norm_violation`；只有"伦理委员会批准"而无编号与机构 → `insufficient_evidence`。

### 6.6 投稿要求（submission）
将目标期刊/会议的作者指南拆成可核对条目，逐条映射到稿件。
- 缺指南 → 标注 `not_checked` + limitations，不编造指南内容；有指南时注明版本与日期。

### 6.7 通用质量（quality / method / statistics / logic）
- quality：标题摘要是否与正文一致、结果是否与图表一致、单位/符号前后一致。
- method：样本量、随机化、盲法、对照组、数据处理是否交代。
- statistics：显著性水平、效应量、置信区间、多重比较校正是否报告；p 值与结论是否对应。
- logic：论证链是否成立、因果措辞是否超出设计（相关≠因果）、前后矛盾。

## 7. 覆盖状态定义

- `checked`：本方向已逐项审查并有明确结论（即使结论是"未发现问题"也要写明"已查，未见 X 类问题"）。
- `pending_review`：已开始但存在证据不足/待确认项。
- `not_checked`：材料缺失或预算不足，尚未覆盖，须在 uncertainty/limitations 说明原因。

## 8. 结论一致性要求

同一输入重复运行，结论应基本一致：脚本正则候选是确定性的；Agent 判定应依赖固定的判定规则（本文件）与原文证据，不随措辞波动。随机因素不引入。
