# 判定规则与误报抑制（audit-rules）

本文件是审查 Agent 的判定规范。脚本（extract.py）只产出**候选观察**（observation），
从不自动给出结论；每一条 observation 都必须经过 Agent 逐条判定后，才能作为 finding
写入 `result.json`。判定目标不是"多列问题"，而是**每条问题都成立、可回查、可核对**。

## 1. 类型（type，四分类）

| type | 含义 | 何时使用 |
|-|-|-|
| `fact_error` | 事实错误 | 数值、事实、元数据与材料内部或其他可核对的来源矛盾，或张冠李戴、引证不实 |
| `insufficient_evidence` | 证据不足 | 论文作出了论断但缺少支持该论断的必要证据/方法/样本/授权描述 |
| `norm_violation` | 规范/合规问题 | 违反可指出的条款、期刊指南、许可范围、伦理或隐私要求 |
| `suggestion` | 建议性意见 | 不构成违规，但按清晰度、完整性、可复现性可改进 |

区分关键：`fact_error` 需要"已有对照证据证明其错"；`insufficient_evidence` 是"缺少必要支撑"；
`norm_violation` 需要"有条款依据"；三者都不成立时，才是 `suggestion`。拿不准时降为
`suggestion` 或标记 `pending_human`，不要强行定错。

## 2. 严重度（severity）

| severity | 含义 | 典型情形 |
|-|-|-|
| `critical` | 影响结论可信度或涉及不可逆合规风险 | 编造数据/引用、伪造批件、泄露受限数据、结论与证据相反 |
| `major` | 影响判断或必须修复才能合规 | 引证与论断不符、方法缺关键参数、伦理批件缺失 |
| `minor` | 影响表达或局部可信度 | 格式不统一、图表编号错、个别元数据不完整 |
| `info` | 仅提示，不影响结论 | 可选补充、风格偏好 |

严重度必须与证据匹配：没有依据把建议写成 critical，也没有依据把真实错误降成 info。

## 3. 每条 finding 的四要素（必须写全）

1. **原文位置**：`file` + `locator`（如 `paper.pdf#L42` 或解析文本的行号），`quote` 必须是原文
   逐字片段（脚本会校验能否回查）。
2. **判定依据**：`basis` 写条款/期刊要求/授权范围原文，注明版本与日期；写不出依据时不报
   `norm_violation`。
3. **严重度**：按第 2 节分级，并与其后果一致。
4. **可执行修改建议**：`revision` 写"改成什么"，不写"建议检查一下"。

## 4. 误报抑制（每条观察先问四个问题）

- **这是问题吗？** 风格差异、学科惯例、个人表述、单复数/时态差异不算违规。
- **证据支持吗？** 能指回原文具体位置并逐字引用，否则降级或排除。
- **有依据吗？** 规范类必须有条款；引用类必须有元数据对照；事实类必须有对照来源。
- **会不会是反面证据？** 同一指标两个来源不一致时，**两个都记录**并标 `source_conflict`，
  不隐瞒冲突。

无法确认的条目写 `pending_human` / `not_reported`，不凭空补结论。citation_analysis 中的
`uncited_references` / `uncited_citations` 只是候选线索（正文可能用作者-年份引用），
必须回到正文逐条核对后才能报出。

## 5. 六个固定方向 + 通用方向（无 case 自带 facets 时的默认检查面）

学术诚信、引用规范、隐私与数据合规、版权与许可、伦理审查、投稿要求；外加通用
质量、事实、方法、统计、逻辑。每个方向都要有"已查 / 待复核 / 未查"结论，不得只挑
最容易的一条出报告。

## 6. 可核验性

同一输入重跑应得到基本一致的结论：证据抽取确定性、判定规则固定、随机性归零。
`change_log` 记录每次增量改动及输入指纹；`quote_verified` / `quote_match_mode` 记录
每条 finding 的回查结果。
