# 判定规则库（source-bound-audit）

本文件是审查 Agent 的判定基准。所有规则都服务同一条原则：**finding 必须指回原文、可复核、可执行；没有原文证据就不得升级为问题**。脚本产出的 pattern 命中只是候选观察，不是结论。

## 1. 类型四分类

| 类型 | 含义 | 何时使用 |
|---|---|---|
| `fact_error` | 材料中的客观事实与可核对的记录（数字、文献、机构、定义、计算）不一致 | 能指出"原文说 X，权威来源/材料内部说 Y"，且 X 可逐字引用 |
| `insufficient_evidence` | 论断超出材料能支撑的范围，或关键方法/数据/授权缺失导致结论无法复核 | 材料确实缺少某条信息，且该缺失影响可信度；不是"我们没查到" |
| `norm_violation` | 违反明确的规范、期刊指南、许可条款或合规要求 | 能指出具体条款/指南版本/授权范围，不能凭"惯例" |
| `suggestion` | 不构成错误或违规，但能提升清晰度、可复核性或规范的改进建议 | 风格、学科惯例、个人表述差异只能落在这一类 |

关键区分：**风格差异、学科惯例、个人表述差异不是 `norm_violation`**；同一事实两个来源不一致且无法判定孰对时，不得报 `fact_error`，应标 `source_conflict` 并记入 `uncertainty` 或 `pending_human`。

## 2. 严重度分级

| 严重度 | 判定标准 | 典型例子 |
|---|---|---|
| `critical` | 使核心结论失效、涉及学术不端、隐私泄露、无伦理审批的人/动物研究、伪造引用或数据 | 编造 DOI、未脱敏的患者信息、结论依赖错误统计 |
| `major` | 影响某条结论或合规状态，需修改后才能提交 | 方法与正文矛盾、关键伦理声明缺失、图表无来源/许可 |
| `minor` | 不影响结论，但不符合规范或影响复核 | 引用格式不统一、统计量未报自由度、声明位置不规范 |
| `info` | 可改进但无规范约束 | 术语前后不一致、建议补充敏感性分析 |

定级后按此顺序复核一遍：若问题只在个别表述而非结论层 → 降一级；若引用/授权/伦理问题影响合规结论 → 保持或升一级。

## 3. 十个检查面（facet）

每个 facet 至少给出 `ok | issues | pending | not_checked` 之一，并写 `summary`。**不得只挑最容易的面报问题**；材料不涉及某面时标 `ok` 并注明"材料不涉及该面"。

### 3.1 academic_integrity（学术诚信）
- 查：数据/图像复用、重复发表、不当署名、利益冲突缺失、致谢与基金不一致、图像篡改迹象。
- 成立要件：能指出"两处内容相同但声明来源不同""作者贡献与署名不符"等可逐字对比的矛盾。
- 抑制误报：无对比材料时"疑似复用"只能标 `pending`；署名顺序争议、共同一作表述不报为违规。
- 依据来源：期刊署名规范、机构诚信条例、材料自身的一致性。

### 3.2 citation（引用规范）
- 查：被引文献是否真实存在、元数据是否与正文一致、正文论断与所引文献是否对应、引而不证、张冠李戴、格式不统一。
- 成立要件：能指出正文引用标签 ↔ 参考文献条目 ↔ 所引文献实际内容之间的可核对矛盾。
- 核实方法：对"承重"引用（结论依赖的引用）用检索工具核实存在性与元数据；对普通引用只查格式与内部一致性，并注明"存在性未逐条核实"。
- 抑制误报：引文格式差异（编号/作者-年份混用之外的风格差异）报 `suggestion`；网络不可用时无法核实的引用记 `pending_human`，不得断言"伪造"。

### 3.3 privacy（隐私与数据合规）
- 查：可识别个人信息、受限数据、未公开数据；是否具备授权或伦理审批依据；脱敏是否充分。
- 成立要件：定位到具体的 PII/受限数据片段，且材料未给出脱敏或授权。
- 抑制误报：已授权的公开数据、作者本人的公开联系方式、已匿名化的编号不报；拿不准是否受限时标 `pending_human`，且**只报位置与类型，不复述、不扩散敏感内容**。

### 3.4 copyright（版权与许可）
- 查：图片、表格、代码、数据集等第三方材料的来源标注、许可类型、复用条件。
- 成立要件：能指出"某图/表/代码无来源/无许可"或"许可类型与复用方式冲突"。
- 抑制误报：作者自制图表的风格问题、开放许可（CC-BY/CC0/MIT 等）下的合法复用不报。

### 3.5 ethics（伦理审查）
- 查：涉及人的研究是否说明知情同意、伦理批件编号与适用范围；动物实验是否符合规范；风险获益表述是否与设计一致。
- 成立要件：能指出"材料报告了人/动物研究但缺少伦理批件/知情同意/动物伦理声明"，或声明与设计矛盾。
- 抑制误报：纯计算/材料学/无生物体的研究标 `ok`（材料不涉及）；批件编号存在但范围不符要写清"哪里不符"。

### 3.6 submission（投稿要求）
- 查：把目标期刊/会议的指南拆成可核对条目，逐条映射到稿件，报缺失、超限、格式冲突。
- 成立要件：必须有指南来源与版本/日期；报出的每条冲突都要写"指南要求 X，稿件现状 Y"。
- 抑制误报：无指南可用时标 `not_checked` 并记入 `errors`/`degradations`，不得凭通用模板编造"投稿要求"。

### 3.7 quality（通用质量）
- 查：摘要/结论是否与正文一致、数字是否前后一致、术语是否统一、单位是否规范。
- 成立要件：材料内部可逐字对比的矛盾（如摘要 n=120 与正文 n=118）。

### 3.8 method（方法）
- 查：方法是否可复现、参数/试剂/设备是否交代、关键步骤是否遗漏、方法描述与结果是否一致。
- 成立要件：能指出"结果依赖的某步骤未交代"或"方法与结果数值无法衔接"。

### 3.9 statistics（统计）
- 查：样本量、效应量、置信区间、P 值、检验方法与假设是否匹配、多重比较是否校正、缺失数据处理。
- 成立要件：能指出"P 值与自由度/检验量不一致""用了配对检验却写成独立检验"等可核对错误。
- 抑制误报：未报效应量/CI 通常报 `suggestion`（除非期刊明确要求）；统计方法选择有争议时标 `pending`。

### 3.10 logic（逻辑）
- 查：论证链是否成立、因果表述是否过度、结论是否被证据支持、循环论证、偷换概念。
- 成立要件：能指出"结论 C 依赖前提 P，而 P 未被材料支持/与材料矛盾"。

## 4. 证据绑定（每条 finding 的硬要求）

每条 finding 必须含：

- `file` + `locator`：源文件与段落定位（如 `materials/paper.md#p3`）。
- `quote`：从原文逐字摘录（允许把换行折叠为空格，但不得改词）。
- `evidence`：用一句话说明"这段原文说明了什么"。
- `basis`：判定依据原文（条款/指南/授权范围/材料内部对比），写清来源与版本/日期。
- `basis_rule`：对应本节规则编号（如 `citation.existence`、`statistics.consistency`）。
- `revision`：可执行修改建议，要能直接落到那一段（"改为 X"而非"建议检查"）。

脚本 `validate.py` 会核对 `quote` 是否能作为规范化子串回查原文；对不上就 FAIL。**宁可删掉一条查不到原文的 finding，也不保留漂移的 quote。**

## 5. 无强制判定（no forced verdicts）

- 每个 facet 都必须有结论，但结论可以是 `ok`（已查，未见问题）。
- 不预设"必须找出几条问题"；材料干净就干净，材料缺证据就 `insufficient_evidence`/`pending`。
- 报 `critical`/`major` 前先反问：这条证据能否经受"换一个人重查也得到同样结论"的检验？不能就降级或转 `pending`。

## 6. 冲突与不确定性

- 两个来源不一致：都记录，标 `source_conflict`，写入 `uncertainty`。
- 无法确认：写 `pending_human` 与 `uncertainty`，不凭空补齐。
- 缺失信息：写 `not_reported`，与"我们没查到"分开表述。

## 7. status 规则（finalize 时自动计算，可覆盖）

- `input_error`：case.json 缺失/不可读，或 contract 无法解析。
- `insufficient_evidence`：无材料、或全部材料解析失败。
- `ok`：所有 facet 已查（ok/issues），且无非 info 严重度、无非 suggestion 类型的 finding。
- `partial`：其余情况（有真实问题，或有 facet 未查，或证据不足但仍有部分结论）。
