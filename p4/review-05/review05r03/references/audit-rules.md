# 判定规则（来源绑定审查）

本文件是逐条判定的口径，不是检查项罗列。核心原则：**候选观察（observation）只是线索，必须人工/Agent 逐条判定成立或排除后才能进入 findings**；漏报真实风险与误报同样扣分。

## 1. 六方向检查要点

### 1.1 学术诚信
- 数据与图像复用、重复发表、不当署名、利益冲突声明缺失、致谢与基金信息不一致。
- 判定依据必须具体：指出哪两处文本不一致、复用的原始出处、署名对应的贡献描述缺失在哪一段。
- 只写"建议补充利益冲突声明"而不指回原文位置，属于无效条目。

### 1.2 引用规范
- 被引文献是否真实存在、元数据是否与原文一致、正文论断与所引文献是否一一对应。
- 识别引而不证（正文结论无对应引文支撑）、张冠李戴（引文内容与论点不符）、格式不统一。
- 核对 DOI/PMID/arXiv 时以实际取得的元数据为准；拿不到就写"无法核实"，不得凭编号猜测文献信息。

### 1.3 隐私与数据合规
- 识别可识别个人信息、受限数据与未公开数据（邮箱、电话、证件号、病例号、未公开数据集）。
- 判断是否具备授权或伦理审批依据；给出脱敏与改写建议。
- **受限数据只标位置与类型，不复述、不扩散敏感内容**；拿不准标 `pending_human`。

### 1.4 版权与许可
- 图片、表格、代码、数据集的来源标注、许可类型与复用条件。
- 指出需要补充授权或替换的位置，并说明所依据的许可条款。

### 1.5 伦理审查
- 涉及人的研究：知情同意、伦理批件编号与适用范围；动物实验：是否符合规范（IACUC/ARRIVE 等）。
- 风险与获益表述是否与实际设计一致；只对能核对的条款下结论。

### 1.6 投稿要求
- 把目标期刊/会议作者指南拆成可核对条目，逐条映射到稿件。
- 报告缺失项、超限项与格式冲突，注明指南版本与日期；指南缺失时标 `not_reported`，不编造要求。

### 1.7 通用质量/统计/方法/逻辑
- 方法是否交代清楚、统计是否完整（样本量、显著性、置信区间、效应量、多重比较校正）、论证链是否成立。

## 2. 类型与严重度

- 类型：`fact_error`（事实错误，可证伪）、`insufficient_evidence`（现有材料不足以支撑某结论）、`norm_violation`（违反规范/合规要求）、`suggestion`（改进建议）。
- 严重度：
  - `critical`：可导致撤稿/违规/数据泄露等严重后果，且证据确凿；
  - `major`：明显影响结论可信度或合规性，需修改；
  - `minor`：局部问题，不影响主体结论；
  - `info`：提示性信息。
- 严重度必须与证据匹配：证据不足时降级或标 `insufficient_evidence`，不得拔高。

## 3. 每条问题的四要素（缺一不可）

1. **原文位置**：`file`（相对 /input 的路径）+ `locator`（`file#p3.L12` 形式）+ `quote`（逐字摘录，可被脚本回查）。
2. **判定依据**：`basis` 写条款/期刊要求/授权范围的**原文与版本/日期**，不写"一般认为"。
3. **严重度**：按第 2 节分级。
4. **可执行修改建议**：`revision` 写具体动作（改哪句、补哪个编号、脱敏成什么），不写"建议完善"。

## 4. 误报抑制（正确性的关键）

- 风格差异、学科惯例、个人表述**不算违规**；判定前先问"能否用条款证伪"。
- 冲突信息（同一指标两来源不一致）**两个都记录**并标 `source_conflict`，不隐瞒。
- 无法确认 → `pending_human` 或 `not_reported`，不凭空补结论。
- 只有位置、无依据的条目降级为 `suggestion` 或删除。

## 5. 证据与可复核性

- 每条 quote 必须能在 `evidence.json` 的归一化文本中找到；`validate.py` 负责机器校验。
- 引用元数据（DOI/题名/年份）只有实际取得时才写入，缺失写 `not_reported`。
- 同一输入两次运行结论应一致：脚本确定性，findings 顺序按 file/locator/type/category 稳定排序。

## 6. 状态计算

- `input_error`：case.json 缺失且无法识别 case_id。
- `insufficient_evidence`：无解析材料且无结论。
- `partial`：六方向未全查，或存在 critical/major 问题，或存在 pending_human。
- `ok`：六方向全 `checked`，且无 critical/major 问题。

## 7. 降级细节

- PDF 解析失败 → degradations 记录失败原因；可用 OCR 时补解析，仍不可得标 `insufficient_evidence`。
- 单文件 >2MB 跳过并记录；坏编码逐级降级（utf-8-sig → utf-8 → gb18030 → latin-1）。
- 缺 `output_contract` → 用标准 schema，标 `contract_missing=true`。
- 缺软件 → limitations 注明，不伪造软件状态。
