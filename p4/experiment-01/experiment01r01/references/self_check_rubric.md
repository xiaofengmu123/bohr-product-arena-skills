# self_check_rubric：评分维度 → 检查项 → 常见失败与修复

本清单用于生成后自检与 `validate` 之外的语义检查。每条对应题目评分维度，
逐条勾选；括号内是该检查项针对的评分点。

## 1. 实际效果（40 分）

- [ ] **任务完成度（15）**：方案以可检验假设开头，不是复述研究目标；六要素都可操作。
  失败样例：步骤写成「准备样品—设置对照—检测分析」，变量只有名字没有操作定义。
- [ ] **正确性（15）**：假设可证伪；变量与测量方式匹配；每个对照写明排除哪类混杂；
  参数在设备/试剂量程内；引用与规格真实无编造。
  失败样例：对照组只有空白组没有阳性对照；参数不写量程却声称「已优化」。
- [ ] **完整性（5）**：假设与变量、对照组、设备材料、时间成本、参数范围、风险与异常
  六项均非空、均有内容。
- [ ] **可核验性（5）**：result.json 有时间戳/change_log/参数来源/金标准；plan.md 与
  result.json 一致；`validate` 退出码 0。

## 2. 使用增益（25 分）

- [ ] **质量增益（15）**：相较不加 Skill，六要素更完整、量程与预算合理、对照有目的；
  做候选方案比较而非只给一个方案。
- [ ] **效率增益（5）**：只产出适配本案例的方案，不堆模板式空话；减少人工修改条目。
- [ ] **增益可验证性（5）**：通过骨架→增量→自检的可核验记录证明改善，不用文字自述代替证据。

## 3. 创新增益（15 分）

- [ ] **新增能力（5）**：至少落实一类基础能力难以稳定实现的点：按量程/预算裁剪参数、
  按研究目标反推对照、生成风险预案与替代路径。
- [ ] **方法改进（5）**：从目标到假设/变量/对照/参数/资源的推演顺序清晰，可复现。
- [ ] **创新证据（5）**：evidence_map 的 `supports` 说明每条证据被哪一处方案消费，
  证据溯源成为可核验事实而非装饰。

## 4. 可靠体验（10 分）

- [ ] **调用与易用性（3）**：按 SKILL.md 能完成一次生成并判断可用；`--help` 可跑。
- [ ] **运行稳定性（4）**：空输入、坏 JSON、坏编码均不崩溃；重复运行结果一致。
- [ ] **异常处理（3）**：输入缺失（无设备参数/预算）、约束冲突（时间窗 vs 样本量）、
  依赖不可用（试剂缺货/设备排期满）、内容不确定均写入 `pending_human` 或 `uncertainty`
  并给出替代路径。

## 5. 生态贡献（10 分）

- [ ] **文档完整性（3）**：输入清单、输出结构、依赖、示例、适用范围、限制齐全。
- [ ] **资源可复用性（4）**：plan/parameter/evidence 模板、对照检查清单、评分锚点可直接复用。
- [ ] **分享推广价值（3）**：沉淀可分享的方案案例、检查清单与实践经验。

## 常见失败 → 修复对照

| 常见失败 | 修复动作 |
|-|-|
| 变量没有单位/量程 | 补 `unit`、`range`、`operational_definition`，并附来源 locator |
| 对照只有空白组 | 补阳性/阴性/剂量梯度，逐条写清排除哪类混杂 |
| 参数越出设备量程 | 按设备手册/合同裁剪区间，写超出区间处置 |
| 时间成本不可排期 | 给步骤时长、并行关系、依赖、总时长、样本量 |
| 预算明细与合计不符 | 修复算术，写 `arithmetic_checks` 供 validate 复核 |
| 结论无出处 | 补 evidence_map.claims 的 locator + 逐字 quote + supports |
| 冲突被隐藏 | 两处来源都记，标 `source_conflict` |
| 未经确认当事实 | 移入 `confirmations`，未确认的写 `pending_human` |
