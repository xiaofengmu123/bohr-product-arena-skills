# 评分维度对齐表（rubric_mapping）

## 2. 六要素 × 检查锚点

| 要素 | 不可接受的写法 | 可复核的最低锚点 |
|-|-|-|
| 假设与变量 | “探究 A 对 B 的影响” | 可证伪假设 + 变量单位/量程 + 混杂清单 |
| 对照组 | 只有“空白组” | 至少一个阳性/阴性对照，各写排除的混杂 |
| 设备材料 | “离心机、培养箱” | 型号 + 量程 + 耗材规格 + 可替代项 |
| 时间成本 | “约一周” | 每步时长 + 并行关系 + 样本量 + 预算算式 |
| 参数范围 | “适宜温度” | 参数 + 单位 + 允许区间 + 超界处置 + 依据 |
| 风险与异常 | “注意安全” | 失败模式 + 判据 + 止损点 + 替代路径 |

## 3. 常见失败与修复（按维度）

| 维度 | 常见失败 | 修复动作 |
|-|-|-|
| 任务完成度 | 步骤写成“准备—设置—检测—分析”套话 | 每步绑定设备/试剂/参数/时长/产出物 |
| 结果正确性 | 参数超出设备量程、对照与研究目标错配 | 用 `parameter_domains` 逐参数核对；对照逐条写“排除何混杂” |
| 结果完整性 | 缺“时间成本”或“风险与异常” | `validate` 六要素检查不通过即补 |
| 可核验性 | 结论无 locator/quote、算术不符 | 补 `evidence`；`validate` 预算/关键路径复核 |
| 使用增益 | 只给一个方案，无比较 | 填 `candidate_comparison`，逐项列量程/预算/排期差异 |
| 创新增益 | 风险只写“注意安全” | 给失败模式→判据→止损→替代的完整链条 |
| 可靠体验 | 空输入崩溃、坏 JSON 中断 | 依赖 `selftest` 的 5 类用例回归 |
| 生态贡献 | 字段随意改名、无示例 | 严格按 `output_contract`；示例标注“示意” |

## 4. 候选方案比较的最小字段（对应创新/使用增益）

`candidate_comparison` 每项建议：

```json
{
  "candidate_id": "plan-A",
  "locator": "candidate_plan_A.md#L1",
  "parameter_fit": "所有参数在量程内/超界项",
  "budget_total": 0,
  "schedule_critical_path_min": 0,
  "control_coverage": "排除的混杂类型",
  "verdict": "select|revise|reject",
  "reason": "依据 locator + 算术结果"
}
```

`arithmetic_validation` 每项建议：

```json
{"check": "budget_total", "expected": 3600, "computed": 3600, "status": "pass", "locator": "resources/price_list.md#L12"}
```

`selected_plan` 指向最终采用/修订后的方案标识，并在 `uncertainty` 写明未选方案的理由与残留风险。

## 5. 评分锚点自评（提交前）

- 实际效果（40）：六要素齐全且可操作，算术全通过，依据可溯源 → 目标 32+。
- 使用增益（25）：3 候选逐项比较 + 算术校验 + 先落盘骨架 → 目标 18+。
- 创新增益（15）：至少一类裁剪/反推/预案落地且有证据 → 目标 10+。
- 可靠体验（10）：selftest 5 类通过、异常有 pending_human → 目标 8+。
- 生态贡献（10）：文档/模板/清单齐全可复用 → 目标 8+。

以上为自评锚点，不代表平台实际评分；实际分数以平台固定案例与对照结果为准，不在技能中编造。
