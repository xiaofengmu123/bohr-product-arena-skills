# 评分维度 → 检查项 → 常见失败与修复

把 SKILL.md 第 6 节的自检清单映射到题目的评分维度；提交前逐项核对。脚本侧可用 `python3 scripts/main.py validate --input /input --output /app/output --work /app/work` 与 `python3 scripts/selftest.py` 辅助。

## 1. 实际效果（40 分）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 目标转成可检验假设，非复述 | 假设写成"研究 A 对 B 的影响" | 写成可判读命题：H1=给药组 X 显著高于溶剂对照组（给出统计/阈值判据） |
| 变量有操作定义/单位/量程 | 只有名字，无测量方式与单位 | 每变量补：测量方式 + 单位 + 取值范围 + 来源 |
| 对照能排除混杂 | 只有空白组 | 阳性/阴性/剂量梯度各写清排除哪类混杂（批间、设备漂移、非特异信号…） |
| 参数在设备/试剂量程内 | 参数超出设备上限 | 交叉核对设备量程，超界改参数或换设备并标注 |
| 引用与规格真实 | 型号/DOI 编造 | 无来源即 `not_reported`；设备/价格来自案例合同则标"案例给定约束" |
| 覆盖六要素 | 缺时间成本或风险 | 六要素逐项非空，见 schema_and_evidence.md 第 2 节 |
| 可复核 | 无来源定位/版本/运行记录 | 每条关键结论带 locator+quote；change_log 记录改动；runtime 写时间 |

## 2. 使用增益（25 分）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 比基础 Agent 更正确/完整/可执行 | 生成模板式目录 | 步骤绑定设备/试剂/时长；参数给区间与超界处置；预算可加总 |
| 效率：减少人工修改 | 结果不可直接排期 | 时间成本给出并行关系与关键路径；确认项单列而非混入步骤 |
| 增益可验证 | 无对照证明 | 用 `arithmetic_checks` 保存可机器复核的算术；候选方案比较写差异表 |

## 3. 创新增益（15 分）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 新增能力 | 与通用流程无差别 | 至少落实一类：按量程裁剪参数、按目标反推对照、风险预案与替代路径 |
| 方法改进 | 候选方案只罗列不比 | 对每个候选做参数/量程/预算/排期算术校验后取舍，并写取舍理由 |
| 创新证据 | 只有文字自述 | 把反推/裁剪/预案的推导链写进 `arithmetic_checks` 或 evidence_map |

## 4. 可靠体验（10 分）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 易触发、可判断可用 | 说明不完整 | 按 SKILL.md 第 2/3/4 节跑通一次；validate 退出码 0 即可用 |
| 稳定、重复一致 | 每次输出不同 | 固定 JSON 键序、无随机性；仅 ts/runtime 允许变化 |
| 异常处理 | 崩溃或编造 | 空输入→insufficient_evidence；坏 JSON/编码→记 errors/degradations 后继续；约束冲突→uncertainty + 两种替代；缺依赖→pending_human |

## 快速自检顺序

1. `python3 scripts/selftest.py` → 全 PASS。
2. 对实际案例：`probe` → `scaffold` → 分析填充 → `patch` → `validate` → 重跑 `validate` 至 USABLE。
3. 确认 `contract_coverage` 全 `filled`，或 `pending_human`/`uncertainty` 已解释每个 `empty` 的缺口原因。
4. 确认 status 诚实、无编造数值/评测分数。
