# 评分维度 → 检查项 → 常见失败与修复

评分维度分值（题目原文）：实际效果 40、使用增益 25、创新增益 15、可靠体验 10、生态贡献 10，GitHub 链接另加 5。本节把维度翻译成可勾选检查项；文字自述不能替代实际运行证据。

## 实际效果（40）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 目标是可检验假设而非复述 | 把 goal 抄一遍当假设 | 写 falsifiable_criterion，给出“什么结果证伪” |
| 变量有操作定义/单位/量程 | 只有变量名 | 补 measurement_method、unit、expected_range |
| 变量与测量方式匹配 | 因变量选了测不到的方法 | 按设备量程反推测量方式 |
| 每个对照排除哪类混杂 | 只有空白组 | 补阳性/阴性/剂量梯度并写明排除的混杂 |
| 参数在设备/试剂允许区间内 | 参数超出量程 | 按合同/手册量程裁剪，标 out_of_range_action |
| 引用与规格真实 | 编型号/DOI/价格 | 全部回溯源材料 locator+quote；缺失写 not_reported |
| 六要素均非空 | 缺某一项 | 对照 references/schema_and_evidence.md 逐项补齐 |
| 版本/来源定位/金标准可复核 | 无 change_log | 记 change_log，参数来源与判读标准写金标准 |

## 使用增益（25）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 质量增益：正确性/完整性/可执行性 | 通用流程模板 | 落到型号、量程、时长、预算、止损点 |
| 效率增益：减少成型时间/返工 | 来回澄清 | 把缺口集中列 pending_human 而非散落正文 |
| 增益可验证：公平对照 | 只自述 | 用同一案例跑基础 vs Skill 并保留两份产物对比 |

## 创新增益（15）

| 检查项 | 落实方式 |
|-|-|
| 新增能力：按量程与预算裁剪参数 | 对每个候选方案跑 arithmetic_checks，超限即裁剪并说明 |
| 方法改进：按研究目标反推对照 | 由假设的证伪判据推出需要哪些对照，而不是套模板 |
| 创新证据：边界与价值 | 说明候选方案比较的取舍依据与可复用模板 |

## 可靠体验（10）

| 检查项 | 要求 |
|-|-|
| 正确触发 | SKILL.md frontmatter 齐备（name/description/version） |
| 易用性 | 按 SKILL.md 第 2/3/4 节可完成一次生成并判断可用 |
| 稳定性 | 空输入→insufficient_evidence；坏 JSON/编码→记录后继续；重复运行一致 |
| 异常处理 | 输入缺失、约束冲突（时间窗 vs 样本量）、依赖不可用（缺货/排期满）、内容不确定 → pending_human/替代路径 |
