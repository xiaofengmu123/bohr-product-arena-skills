# 自检清单：评分维度 → 检查项 → 常见失败与修复

提交/交付前逐条核对；`scripts/selftest.py` 覆盖其中可自动化的鲁棒性项。

## 1. 实际效果（40 分）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 目标已落成可检验假设，而非复述 | 开头直接抄研究目标 | 写成“若…则…”，变量可测量 |
| 自变量/因变量有操作定义、单位、量程 | 变量只有名字 | 补测量方式 + 单位 + 允许区间 |
| 每个对照写明排除哪类混杂 | 只有空白组 | 按目标补阳性/阴性/剂量梯度 |
| 参数在设备/试剂量程内 | 数值超出量程 | 查设备手册/合同，越界即改或标 pending_human |
| 六要素均非空 | 缺风险或缺参数 | 按 references/plan_schema_and_evidence.md 补齐 |
| result.json 含版本/来源/金标准/change_log | 无 change_log | 每次大改动追加 `{ts, event, detail}` |
| plan.md 与 result.json 一致 | 两处数字不一致 | 以 result.json 为准回写 plan.md |

## 2. 使用增益（25 分）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 候选方案比较有算术依据 | 只写“方案 A 更好” | 抽参数/成本/时长做量程+预算+排期校验 |
| 参数裁剪有据 | 直接删参数 | 写明裁剪依据（量程/预算/目标） |
| 可复现 | 步骤不可重跑 | 固定键序、无随机、脚本确定性 |

## 3. 创新增益（15 分）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 按目标反推对照 | 模板式对照 | 从假设推“需排除哪类混杂”再定对照 |
| 按量程与预算裁剪参数 | 与目标脱节 | 以有限参数域为边界裁剪 |
| 风险预案含止损点与替代路径 | 只写“注意安全” | 补判据、止损点、替代路径 |

## 4. 可靠体验（10 分）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 空输入不崩溃 | 抛异常 | status=`insufficient_evidence`，退出码 0 |
| 坏 JSON/坏编码继续 | 中断 | 记 `errors`/`degradations` 继续处理其余材料 |
| 缺参数有默认 | 无默认路径 | `--input/--output/--work` 默认 `/input`、`/app/output`、`/app/work` |
| 超大文件跳过 | 内存/卡死 | >2MB 跳过并记 `degradations` |
| 约束冲突被识别 | 掩盖冲突 | 写 `uncertainty` + 两种替代 + 需专家确认 |
| 重复运行一致 | 键序/随机抖动 | 固定 JSON 键序、无随机种子 |

## 5. 生态贡献（10 分）

| 检查项 | 常见失败 | 修复 |
|-|-|-|
| 输入清单/输出结构/依赖/示例/限制齐全 | 只有 SKILL.md | 附 references 两份 + 最小调用示例 |
| 模板与清单可复用 | 与本题耦合 | 六要素模板、算术校验规则独立成文 |
| 示例标明“示意” | 冒充正式答案 | 示意输出显式标注，不写预生成答案 |

## 自动化自检

```bash
python3 scripts/selftest.py          # 空输入/坏 JSON/超大文件/越界参数/契约回填/确定性
python3 scripts/main.py validate --input /input --output /app/output --work /app/work
```
