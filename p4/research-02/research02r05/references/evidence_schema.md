# 证据组织与写作规则

本文件是 `evidence_table.jsonl`、`screening_log.json` 与综述草稿的字段级规范，
保证"每条实质论断都能反向查到证据行"。

## 1. 证据行字段（evidence_table.jsonl，每行一个 JSON）

| 字段 | 必需 | 说明 |
|-|-|-|
| `evidence_id` | 是 | 唯一标识，如 `E001` |
| `source_id` | 是 | 指回 sources 表中的来源 |
| `locator` | 是 | 文件 + 页码/段落，如 `materials/paper.pdf#p3` 或 `materials/p1.txt#para2` |
| `quote` | 是 | **逐字原文**，不改写、不意译 |
| `claim` | 是 | 该证据支撑的论断（一句） |
| `strength` | 是 | 见 §2 四级 |
| `field` | 是 | 比较字段：研究对象/方法/样本量/主要结果/结论/局限/未报告项 |
| `notes` | 否 | 冲突、去重、来源冲突等说明 |

## 2. 证据强度四级

| strength | 判定 | 综述措辞 |
|-|-|-|
| `established` | 多源一致且方法充分 | 表明 / 证实 |
| `suggestive` | 单源或方法有限 | 提示 / 初步表明 |
| `disputed` | 存在结论冲突或方法互斥 | 存在争议 / 结论不一 |
| `not_reported` | 该指标未见报告 | 未见报告 |

**"未见报告" ≠ "不存在"**：只写"该文献集内未见报告"，不反向断言。

## 3. 综述草稿（review.md）规则

- 每段对应一组证据；每条实质论断带 `[S#]`，指向 evidence_table 行的 `evidence_id`。
- 措辞与 strength 严格一致；`established` 用"表明/证实"，`suggestive` 用"提示/初步表明"。
- 冲突结论并列呈现并标 `disputed`；不抹平反面证据，不把相关写成因果。
- 文末附 sources 表：真实来源，含元数据与定位；不虚构文献/DOI/数值。
- 研究空白落到具体证据缺口（哪些问题没有任何文献覆盖），不用套话收尾。

## 4. 筛选记录（screening_log.json）规则

- `criteria` 必须写在 `decisions` **之前**（先写标准，再逐篇纳排）。
- 纳入/排除标准含四要素：研究对象、纳入条件、排除条件、去重规则。
- 每条决定可回溯：`source_id`、`decision`（include/exclude/duplicate）、`reason`。
- 去重按 SHA-256 内容哈希 + 题名/DOI 近似匹配；只保留一份入证据表。

## 5. 禁止事项

- 虚构文献、DOI、数值、页码。
- 跨文档串值（把 A 文数值填进 B 文）。
- 把摘要当全文证据（仅有摘要的源标 `abstract_only`）。
- 把相关写成因果、把未报告写成不存在。
- 编造评测分数或运行结果（预算、追踪由平台记录）。

## 6. 主题归纳（themes.md）规则

- 主题从证据聚类生成（方法、对象、结论分歧），**不套**"背景/方法/挑战/展望"通用框架。
- 每个主题列出支撑文献与边界，避免主题间重叠或遗漏。
