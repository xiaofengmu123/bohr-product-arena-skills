# 自检清单（对应评分维度）

评分 100 分，五维合计；本清单与 `scripts/selftest.py`、
`scripts/validate_output.py` 配合，前 3 分钟先落盘骨架，之后增量改进。

## 实际效果（40 分）
- [ ] 七要素齐全：意见拆解、逐条回应、修改定位、证据补充、语气控制、版本一致性、
      预期交付（回复信 + 修订稿 + result.json）。
- [ ] 每条意见及其多个子要求都被拆出并给出明确处理结论，无笼统致谢或只答一半。
- [ ] 每条“已修改”声明都有 `locator` + `quote_after`（逐字），能在指定版本稿件中被找到。
- [ ] 需补实验/数据/文献/重做分析的意见给可查证证据，或说明为何无法补做并给替代方案。
- [ ] 回复信、修订稿、版本标记三者一致；每处定位独立可核验。
- [ ] 事实、数字、引用、专业判断准确；“已修改”声明与稿件真实状态一致。

## 使用增益（25 分）
- [ ] 提供可复跑的对照方式：同输入下加载/不加载 Skill 对比，而非仅文字自述。
- [ ] 意见拆解→逐条回应→修改定位→证据补充的流水线减少逐条比对、查行号、重写语气的时间。
- [ ] 增益结论有公平对照与逐条证据支撑（证据在 `evidence_map` 与 `change_log`）。

## 创新增益（15 分）
- [ ] `comment_registry`（拆解台账：类型/严重度/子要求/决策/语气）为基础 Agent 难稳定实现的能力。
- [ ] `evidence_map`（逐字 before/after + locator + anchor + verified）为可复核定位的实质改进。
- [ ] 方法边界清晰：只做受控修订演练，不冒充完整返修系统、不编造实验。

## 可靠体验（10 分）

- [ ] 缺材料先列 `material_gaps` 再标假设推进；缺软件/缺数据如实标注 limitations。
- [ ] 意见冲突、意见有误、稿件缺章节、无法补实验、版本不匹配、权限不足分别处置。
- [ ] 长稿件、多意见、多轮返修、重复运行下要素不漂移、目标与版本前后一致。

## 生态贡献（10 分）
