# 自检清单（对应评分维度，逐条勾选）

执行前必查（0–3 分钟）：

- [ ] 已读 `/input/case.json` 与 `task.md` 原文，未按文件名臆测内容；已扫 `/input/materials/`。
- [ ] 前 3 分钟已用 `scaffold.py` 落盘 `status=partial` 的 result.json 骨架与五个交付文件。
- [ ] 每次修改追加 `change_log`，改后重跑 `check_revision.py`，最终跑 `selftest.py` 退出码 0。

实际效果（40 分）：

- [ ] 每条意见及其中每个子要求都有明确处理结论；无空泛致谢、无只答一半。
- [ ] 每处"已修改"声明与 `revised_manuscript.md` 真实状态一致，`anchor` 可被 `check_revision.py` 独立检索核对。
- [ ] 每条数字/术语/引用/关键论断有 `fact_source_mapping` 条目，含逐字 `quote`，不新增材料外事实。
- [ ] 需补证意见有证据清单：到位状态 + 出处 + 无法补做说明；回复信、修改稿、版本三者一致（同一 comment_id 与 anchor）。

可靠体验（10 分）：

- [ ] 缺材料先列 `material_gaps`，再按 `assumption` 推进并标注；冲突信息双记并标 `source_conflict`。
- [ ] 重复运行要素不漂移：意见编号、决策、语气、anchor、版本前后一致；失败/异常分别说明。
- [ ] 空输入、坏 JSON、坏编码、缺文件均退出码 0 并写合法 result，不崩溃不编造。

使用增益（25 分）：

- [ ] 意见拆解 + 六列台账把"逐条比对意见、人工查行号、重写语气、补证据清单"从人工改为结构化可复跑。
- [ ] 提供公平对照方式：同输入先跑 `scaffold.py` 得基线骨架，再加载本 Skill 得台账，diff 即增益证据（不靠文字自述）。

创新增益（15 分）：

- [ ] 形成基础 Agent 难稳定实现的能力：意见拆解、`旧→新` 定位锚点机检、证据状态机、语气四档、多轮台账。
- [ ] 方法实质改进而非包装：`check_revision.py` 能机检"改得准/对得上"，而非仅叙述性自述。

生态贡献（10 分）：

- [ ] 说明、输入模板、依赖（仅标准库）、示例、边界、维护信息齐全；`references/` 分类法与模板可直接复用。
- [ ] `revision_ledger.json` 台账、回复信模板、定位表、评分锚点（答得全/改得准/证得住/对得上）可被他人复用。

降级核对：

- [ ] 意见有误/冲突 → 礼貌反驳或澄清 + `source_conflict`；无法判断 → `pending_human`，不硬填。
- [ ] 无法补实验 → `not_feasible` + 原因 + 替代方案；不冒称已补做。
- [ ] PDF 无法解析/版本不匹配/权限不足 → 记入 `anomalies`，相关条目 `unverified`，用可得材料推进。
