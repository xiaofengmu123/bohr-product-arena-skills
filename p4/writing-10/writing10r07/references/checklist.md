# 自检清单（对应评分维度）

逐条勾选；`scripts/selftest.py` 自动复核带「机检」标记的条目，其余为人工/Agent
执行时逐条核对。

## 实际效果（40 分）
- [ ] 意见全覆盖：`comment_index` 中每条意见在台账中都有一行（机检：ledger_ids / ledger_unique）。
- [ ] 子要求全覆盖：一条意见内的多个子要求都有明确处理结论，不笼统致谢、不只答一半。
- [ ] 每条 accept/partial 决策都有具体 `action`，不是"已修改"空话（机检：action_complete）。
- [ ] 每处修改都有 `manuscript_location`，且能在修订稿中被找到（机检：location_resolvable）。
- [ ] 事实/数字/引用准确，与 `fact_source_mapping` 逐条对应，不新增材料外事实。
- [ ] 语气分级正确：接受/澄清/礼貌反驳/申诉四种，不冒犯、不过度承诺、不无原则顺从（机检：tone_values）。

## 使用增益（25 分）
- [ ] scaffold.py 在首分钟内完成意见抽取与台账骨架，减少逐条比对意见、查行号、重写语气的时间。
- [ ] 回复信由台账生成，避免逐条来回改；每个定位可独立核对。
- [ ] 增益可验证：`selftest.py --report` 输出逐条证据，可复跑对照加载/不加载 Skill 的差异。

## 创新增益（15 分）
- [ ] 意见—改动—证据三栏台账是基础 Agent 难以稳定实现的能力，把"对得上"变成可机检结构。
- [ ] 定位用「行号/章节/标题/原文片段」四选一，改稿后仍可解析，而非写死页码。
- [ ] 证据清单区分 `done/partial/not_done/impossible`，无法补做时必给替代说明。

## 可靠体验（10 分）
- [ ] 模糊请求先索要审稿意见、指定稿件版本、期刊格式与权限。
- [ ] 空输入目录→`insufficient_evidence`；坏 JSON/坏编码→记录后继续；缺参数→默认 `/input`、`/app/output`、`/app/work`。
- [ ] 超大文件（>2MB）跳过并记录；写盘失败降级到最小合法 result.json。
- [ ] 重复运行结果一致（scaffold 确定性：文件列表排序、无随机状态）。
- [ ] 意见互相冲突/意见本身有误/稿件缺章节/无法补实验/版本不匹配：识别并分别标注。

## 生态贡献（10 分）
- [ ] 使用说明、字段 schema、示例、适用边界、维护信息齐全（见 `references/elements.md`）。
- [ ] 意见分类法、回复信模板、定位脚手架、台账 schema 可被他人直接复用。
- [ ] 不预写正式案例答案，不冒称真实补做实验、原稿已改、编辑部已接收。

## 执行前必查
- [ ] 已读 `/input/case.json` 与 `task.md` 原文，未按文件名臆测内容。
- [ ] 首 3 分钟内已运行 scaffold.py 并落盘 partial 骨架。
- [ ] 每次修改追加 change_log；最终先跑 selftest.py，再跑 validate_output.py。
