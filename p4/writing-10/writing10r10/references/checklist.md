# 自检清单（对应评分维度）

执行 `python scripts/selftest.py` 覆盖脚本级自检；下列清单由 Agent 在运行时逐条勾选。

## 实际效果（40 分）

- [ ] 每个案例交付：可编辑修改稿、逐条回复信、修改定位表、未到位证据清单四件套。
- [ ] 每条意见都被拆成 `sub_requirements`，每条子要求有 `disposition`（答得全）。
- [ ] 每条意见有 `decision` + `tone` + `response`，无笼统致谢、无答非所问。
- [ ] 每处「已修改」在 `locations` 中给出 `before`/`after`，且 `anchor_status=verified`
      的断言在基线稿与修改稿中均可逐字找到（改得准）。
- [ ] 需补实验/数据/文献的意见有 `evidence` 条目，`status` 如实（证得住）。
- [ ] 回复信引用的位置与修改稿、台账三者一致，多轮承诺沿用同一 `id`（对得上）。
- [ ] 每条论断可定位到 `source_ref`，数字与阈值有依据，不新增材料外事实。

## 使用增益（25 分）

- [ ] `main.py all` 一条命令可从输入产出骨架 + 检查报告 + 四件套，减少逐条比对工作量。
- [ ] 台账一次维护、四处渲染（回复信/定位表/证据清单/自动修改稿），避免手工重复。
- [ ] 对照方式可复跑：同输入不加载 Skill 与加载 Skill 各跑一次，差异以检查报告为证。

## 创新增益（15 分）

- [ ] 台账优先（Ledger-first）：以 `revision_ledger.json` 为单一事实来源，派生件不再漂移。
- [ ] 稳定锚点定位：改前/改后逐字摘录 + 章节名，替代易失效的页码行号。
- [ ] 校验顺序「覆盖→对齐→证据→语气」对应题目四问（答得全/改得准/证得住/对得上）。

## 可靠体验（10 分）

- [ ] 空输入 / 坏 JSON / 坏编码均退出码 0，写合法 `result.json`，不崩溃。
- [ ] 重复运行同一输入，除时间戳与 `change_log` 外结果一致（确定性）。
- [ ] 材料缺章节、意见冲突、意见有误、无法补实验、版本不匹配分别记录到
      `material_gaps` / `anomalies` / `pending_human`，不硬填、不编造。

## 生态贡献（10 分）

- [ ] 使用说明、依赖（仅标准库）、输入模板、示例、边界与维护信息齐全。
- [ ] 台账 schema、意见分类法、回复信模板、定位脚手架与检查脚本可被他人直接复用。
- [ ] 沉淀可分享的返修台账与意见分类经验，说明与提交版本一致。

## 执行前必查

- [ ] 已读 `/input/case.json` 与 `task.md` 原文，未按文件名臆测内容。
- [ ] 前 3 分钟已落盘 `status=in_progress` 骨架（`scaffold`）。
- [ ] 每次修改追加 `change_log`，重跑 `check`，最终跑 `merge` 定稿。
