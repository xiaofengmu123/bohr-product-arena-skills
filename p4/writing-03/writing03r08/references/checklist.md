# 自检清单（评分维度对齐）

交付前逐条勾选。每条的"对应维度"说明它保护的是哪个评分点；未勾选即未达到可交付状态，须先修复或如实标注。

## A. 实际效果（40 分）

- [ ] **任务完成度**：可编辑成品（`.docx`/`.tex`/`.md`）已生成，且渲染预览（PDF/PNG）已产出并回填 `deliverable` 路径。
- [ ] **结果正确性**：`style_spec` 每项都对照模板实测值填写，字号/行距/页边距/栏数/题注位置/参考文献样式与目标模板一致；正文、图表、公式、引用、批注未被错误改动。
- [ ] **结果完整性**：`style_spec` 覆盖页面/字体/标题层级/图表/参考文献/页眉页脚/导出七类；`content_units` 覆盖正文、标题、图表、公式、脚注、批注、修订、域代码、分节符、目录、交叉引用、嵌入对象、题注。
- [ ] **结果可核验性**：`python scripts/main.py verify` 退出码 0；每条 `quote` 能在材料文本中定位，`verification_report.json` 已生成。

## B. 使用增益（25 分）

- [ ] **质量增益**：先跑 `scaffold` 落盘 partial 骨架，再做增量改进；每次改动写入 `change_log`，不整体重建。
- [ ] **效率增益**：四问流程（认得准→排得对→转得全→交得出）减少逐项核对与重复排版；规格检查项一次抽取、全程复用。
- [ ] **增益可验证性**：`scripts/selftest.py` 通过；`change_log` + `verification_report.json` 构成"输入→成品"的复现路径。

## C. 创新增益（15 分）

- [ ] **新增能力**：`style_spec` 从模板文件反推检查项清单，而非凭经验猜测（认得准）。
- [ ] **方法改进**：内容单元用 `unit_id + quote + locator` 锚定，转换前后保真可核对（转得全）。
- [ ] **创新证据**：`version_boundary.diff` 逐条记录改前/改后/理由，交叉引用与编号联动更新的改动可追溯。

## D. 可靠体验（10 分）

- [ ] **调用与易用性**：SKILL.md 的脚本调用用相对路径 `scripts/xxx.py`；`--case/--out/--work` 缺省指向 `/input`、`/app/output`、`/app/work`。
- [ ] **运行稳定性**：空输入、坏 JSON、坏编码、缺 `output_contract` 均降级为合法 partial，不崩溃；重复运行结果一致。
- [ ] **异常处理**：模板缺失/版本不明、字体缺失、样式冲突、转换失败、内容无法保真，均写入 `uncertainty.limitations` 与 `pending_human`。

## E. 生态贡献（10 分）

- [ ] **文档完整性**：SKILL.md 写清用途、适用条件、调用方式、输入输出、异常处理、限制与维护信息。
- [ ] **资源可复用性**：脚本仅依赖标准库；`references/` 的检查框架与证据规范可被他人复用。
- [ ] **分享推广价值**：检查项清单、证据锚定规范、最小调用示例（标明为示例）随包交付。

## 硬性失败项（出现即 `verify` 退出码 2）

- `case_id` 与 `/input/case.json` 不一致。
- `result.json` 缺 `output_contract` 字段或缺保留字段 `status/sources/uncertainty/change_log`。
- 残留 `TODO`/`待补`/占位符标记。
- JSON 无效、无法解析。

任何一条硬性失败都先修复；无法修复时保持 `status=partial` 并写明 `limitations`，绝不编造评测分数、运行结果、文献元数据或科学数据。
