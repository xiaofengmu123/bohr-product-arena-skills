# 自检清单与降级规则（Checklist & Degradation）

收口前逐条勾选；未通过时按右侧动作处置。脚本侧自动化项标注 `[脚本]`。

## 0. 评分维度 → 清单映射（对应关系）

| 评分维度 | 分值 | 本清单对应节 | 关键抓手 |
|-|-|-|-|
| 实际效果 | 40 | A/B/C/D | 章节稿而非提纲；数值/单位/样本量/图注/DOI 与材料一致；章节图表声明齐备；逐条可回溯、改动留痕 |
| 使用增益 | 25 | B/C/E | 相同材料下可用程度提升；返工条目下降；对照公平（同模板/字数/引用格式/权限） |
| 创新增益 | 15 | B/C | 材料-图表-正文三向对齐、论断-引用绑定、缺项检测、术语统一（本包以 locator+逐字 quote 的证据映射为核心新增） |
| 可靠体验 | 10 | F/G/H | 常见材料可喂入；换学科/篇幅/完整度稳定；缺图注/冲突/无全文/超长/格式不认识的识别处置 |
| 生态贡献 | 10 | 全部 + conventions.md | SKILL.md、模板、格式、依赖、示例、适用范围齐全；脚本可复用 |

## A. 输出契约（可核验性）

- [ ] `/app/output/result.json` 存在且为合法 JSON（`json.load` 可读）`[脚本 check]`
- [ ] 含 `case_id`，与 `/input/case.json` 的 `id`/`case_id` 一致 `[脚本 init]`
- [ ] 含 output_contract **全部字段**，未知键不删不改名，缺失值给 `null`/`[]`
- [ ] 含 `status` / `sources` / `uncertainty` / `pending_human` / `change_log`
- [ ] `status` 与实际完成度一致；有缺项用 `partial`，不得虚标 `complete`
- [ ] `change_log` 从骨架到成稿的每次改动留痕（ts/step/note）

## B. 事实一致（写得实）

- [ ] 稿件是完整可编辑章节稿，不是提纲 / 写作建议 / 素材堆叠
- [ ] **每个数值/单位/样本量/显著性/图注都挂 `[S:claim_id]`，无裸数字**
- [ ] 每条 claim 在 material_index 有 `locator` + **逐字 quote**，quote 来自材料原文字串 `[脚本 evidence]`
- [ ] 正文没有凭领域常识补写、材料中不存在的事实；补写处标 `[待确认]`
- [ ] 摘要与结果、正文与图注、方法与步骤之间无未说明冲突；冲突标 `[冲突待确认]`

## C. 引用对应（引得对）

- [ ] 每条 `[C:key]` 在文末参考文献区有定义，作者/年份/期刊/卷期/DOI 与给定文献一致
- [ ] 每条引用真正支撑所在句，无装饰性、无错配；索引中"已定义未使用"条目已清理 `[脚本 evidence]`
- [ ] DOI/卷期缺失写 `unknown`，不杜撰；取不到全文只依给定元数据引用
- [ ] 无悬空 `[S:]` / `[C:]` 标记 `[脚本 evidence]`

## D. 章节完整（全得起来）

- [ ] 覆盖题目/学科模板要求的摘要、引言、方法、结果、讨论、结论、参考文献、数据可得性声明等
- [ ] 图/表编号连续无缺号 `[脚本 check]`；图注齐备，缺图注标 `[缺失]`
- [ ] 声明字段（利益冲突、数据可得性、作者贡献等）齐备或显式标注 `[缺失]`

## E. 可编辑性（改得动）

- [ ] 稿件保留 Markdown 章节层级、图注编号、引用格式
- [ ] 可直接在 Word/Markdown 继续修改并逐条复核
- [ ] 要求 docx/xlsx/pptx 时，已另渲染真实 PDF/PNG 预览供检查

## F. 降级策略（缺数据/缺软件）

规则：**缺什么标什么，绝不编造。** 无法产出部分写 `partial`，在 `uncertainty`/`change_log` 说明 limitations。

| 情况 | 处置 |
|-|-|
| PDF 解析工具缺失/失败 | 用可用工具（pdftotext/渲染/OCR）；失败标 `[无法解析]`，不凭文件名/标签补内容 |
| 图表缺图注 | 图注标 `[缺失]`，正文相应描述标 `[待确认]`，计入 `uncertainty` |
| 文献取不到全文 | 仅用给定元数据引用；缺失字段写 `unknown`，禁止补 DOI |
| 材料间数值/口径冲突 | 并列各方+来源，标 `[冲突待确认]`；需取舍时显式声明依据 |
| 材料超长 | 按可用部分产出 `partial`，说明未处理部分及原因 |
| 引用格式不认识 | 统一为 `[C:key] 作者. 题目. 期刊 年份;卷(期):页. DOI` 最小可核格式 |
| 脚本运行失败 | 保留已落盘骨架，手工补字段，如实记录失败原因到 `errors` |

## G. 收口前最后三查 `[脚本 check]`

1. result.json 能被 `json.load` 正常读取；
2. `sources` 每条 `claim_id`/`ref_id` 都能在 material_index 或文献条目中找到；
3. `uncertainty` 覆盖全部 `[待确认]`/`[缺失]`/`[冲突待确认]`/`[无法解析]`/`[待核]` 标记。

## H. 提交前自检 `[脚本 selftest]`

```bash
python3 -B scripts/main.py --help        # 退出码 0
python3 -B scripts/selftest.py           # 退出码 0（最小夹具全流程）
```

空目录、坏 JSON、缺输入三种情况均需验证：写合法 result.json、不抛异常、状态诚实。
