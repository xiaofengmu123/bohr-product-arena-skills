# 自检清单与降级规则（checklist）

收口前逐条勾选；未通过按右侧动作处置。清单按评分维度组织。

## A. 输出契约（可核验性，对应「实际效果·可核验性 / 可靠体验·调用」）

- [ ] `/app/output/result.json` 存在且可被 `json.load` 读取
- [ ] 含 `case_id`，与 `/input/case.json` 一致
- [ ] 含 output_contract **全部**字段，不改名、不删未知键，缺值给 `null`/`[]`
- [ ] 含 `status`/`sources`/`uncertainty`/`pending_human`/`change_log`
- [ ] `status` 与实际完成度一致（有缺项用 `partial`，不虚标 `complete`）
- [ ] `change_log` 记录从骨架到成稿的每次改动
- [ ] 已运行 `python3 scripts/selftest.py --check` 且零 error

## B. 写得实（事实一致，对应「结果正确性 15 分」）

- [ ] 稿件是完整可编辑章节稿，不是提纲、写作建议或素材堆叠
- [ ] 每个数值/单位/样本量/显著性/图注都有 `[S:材料ID]` 且能指回材料位置
- [ ] 证据目录里每条 claim 有 locator + 逐字 quote
- [ ] 没有凭领域常识补写材料外事实；补写处已标 `[待确认]`
- [ ] 摘要与结果、正文与图注、方法与步骤之间无未说明冲突
- [ ] `evidence.py check --draft`：无悬空来源、无悬空引用、无未标注的数值行

## C. 引得对（引用对应，对应「结果正确性·作者/年份/期刊/DOI」）

- [ ] 每条 `[C:键]` 在参考文献区有定义，作者/年份/期刊/卷期/DOI 与给定文献一致
- [ ] 每条引用真正支撑所在句，无装饰性、无错配引用
- [ ] DOI/卷期缺失写 `null`/`unknown`，不杜撰；取不到全文只用给定元数据
- [ ] `evidence.py check`：无 `E_CIT_UNDEFINED`、无"已定义未使用"

## D. 全得起来（章节完整，对应「结果完整性 5 分」）

- [ ] 覆盖摘要、引言、方法、结果、讨论、结论、参考文献、数据可得性声明等关键部分
- [ ] 图表、表格、声明字段齐备；缺项标 `[缺失]` 或写入 `uncertainty`
- [ ] `selftest.py --check`：无章节缺失告警、Figure/Table 编号无缺号

## E. 改得动（可编辑，对应「可编辑性/增益」）

- [ ] 稿件保留 Markdown 层级、图注编号、引用定义行，可继续修改并逐条复核
- [ ] 要求 docx/xlsx/pptx 时，已另渲染真实 PDF/PNG 预览

## F. 降级策略（异常处理，对应「可靠体验·异常处理 3 分」）

规则：**缺什么标什么，绝不编造。** 无法产出的部分写 `partial`，在
`uncertainty`/`change_log` 说明 limitations。

| 情况 | 处置 |
|-|-|
| PDF 解析工具缺失/失败 | 用可用工具；失败标 `[无法解析]`，不凭文件名/标签补写内容 |
| 图表缺图注 | 图注标 `[缺失]`，正文描述标 `[待确认]`，计入 `uncertainty` |
| 文献取不到全文 | 仅用给定元数据引用；缺失字段写 `null`/`unknown`，禁止补 DOI |
| 材料间数值/口径冲突 | 并列各方 + 来源，标 `[冲突待确认]`；取舍时显式声明依据 |
| 材料超长 | 按可用部分产出 `partial`，说明未处理部分及原因 |
| 引用格式不认识 | 统一为 `[C:键] 作者. 题目. 期刊 年份;卷(期):页. DOI` 的最小可核格式 |
| 脚本运行失败 | 保留已落盘骨架，手工补字段，如实记录失败原因 |

## G. 收口前最后三查

1. `result.json` 能被 `json.load` 正常读取；
2. `sources` 每条 `ref_id` 都能在材料索引或文献条目中找到；
3. `uncertainty` 覆盖全部 `[待确认]`/`[缺失]`/`[冲突待确认]`/`[无法解析]` 标记。

## H. 提交前自检（运行一次）

```bash
python3 -B scripts/selftest.py --selftest
```

三种降级场景（空输入、坏 JSON、正常输入）均须退出码 0 且产物合法。
