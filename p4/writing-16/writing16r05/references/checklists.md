# 改写自检清单（对应评分维度）

本清单供 Agent 在改稿中、改稿后逐项勾选，也供原作者复核。每项只在"有证据支持"时勾选，
证据来自源文逐字片段；不满足的项目写入 result.json 的 `pending_human` 或 `uncertainty`。

## 一、读得懂（受众适配 / 任务完成度）

- [ ] 已从 case.json/task.md 明确：目标读者、阅读目的、体裁、篇幅上限。
- [ ] 缩写首次出现处全部展开为全称（并保留缩写），文末可附术语表。
- [ ] 未解释的公式、领域行话已替换为通俗表达或补充一句解释。
- [ ] 比喻/例子与源文机制一致，没有引入源文不存在的新事实。
- [ ] 成品是"可直接使用的完整稿件"，不是提纲、建议或片段润色。

## 二、留得住（内容取舍 / 结果完整性）

- [ ] 关键结论、数据、单位、样本量 n/N、比较基准、图表编号全部保留。
- [ ] 方法要点、限定条件（研究对象、条件、时间窗、置信区间等）未丢失。
- [ ] 删除的是冗余（重复、铺陈、过渡），不是证据。
- [ ] 每条被删/被改内容都在 change_log 中记了理由与原文定位。

## 三、说得准（科学事实 / 结果正确性）

- [ ] 数值、单位、百分数、样本量与源文一致，未四舍五入或换算失真。
- [ ] 相关≠因果、初步≠定论：论断强度与源文动词一致。
- [ ] 未新增源文没有支持的结论；推断与源文事实分开标注。
- [ ] 同一概念全文只有一个说法（术语已锁定，见术语表）。

## 四、接得住（可核验 / 可靠体验）

- [ ] 提供逐段对照或改动清单：每项含 locator + 逐字 quote + 理由。
- [ ] 材料不足、数据冲突、涉密/未发表、体裁与篇幅冲突均已标注。
- [ ] result.json 的 status 诚实：不足就写 insufficient_evidence，不编造。
- [ ] 主产物可编辑（.md/.docx 等），并已由 verify.py 通过或记录缺口。

## 评分维度 → 检查点速查

| 评分维度 | 分值 | 对应清单 |
|-|-|-|
| 实际效果 | 40 | 一（完成度）+ 三（正确性）+ 二（完整性）+ 四（可核验性） |
| 使用增益 | 25 | 二、三（质量）+ 四（效率与可验证对照记录） |
| 创新增益 | 15 | 受众画像→取舍策略→边界标注→多文体映射链路 |
| 可靠体验 | 10 | 触发清晰 + 重复运行稳定 + 异常处理 |
| 生态贡献 | 10 | SKILL.md/模板/术语表/验收口径/失败处理/版本信息 |
