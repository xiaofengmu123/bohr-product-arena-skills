# 验收口径与异常处理清单（references）

本文件给出可勾选的验收口径与异常降级规则，供 Agent 在 S6 自检与交付前核对。

## 1. 验收口径（逐条核对）

- [ ] result.json 存在且为合法 JSON，含 `case_id` 与 case.json `output_contract` 的全部字段
- [ ] 主产物为可编辑文本（.md/.docx/.json/.csv），写入 /app/output/，路径在 result.json `artifacts` 中
- [ ] 每个关键数字/术语/引用/图表/论断在 `sources` 有 locator + 逐字 quote
- [ ] `change_log` 覆盖每段删改：原文位置 → 改后文本 → 改动类型 → 理由 → 待确认项
- [ ] `uncertainty` 标注证据强度（确定/初步/相关/未报告）与冲突、缺口
- [ ] 无源材料之外的新事实/新结论/新引用；无编造分数或实验数据
- [ ] status 诚实：`ok`（完整可用）/`partial`（有限制但可复核）/`insufficient_evidence`（材料不足）/`input_error`（输入不可读）

## 2. 异常处理（不崩溃，如实标注）

| 场景 | 处置 | 记录位置 |
|---|---|---|
| 空输入目录 | 写合法 result.json，status=insufficient_evidence，退出码 0 | status + pending_human |
| 坏 JSON | 捕获异常，继续处理其余材料 | errors + degradations |
| 坏编码 | 按 utf-8-sig→utf-8→gb18030→latin-1 降级 | degradations |
| 单文件 >2MB | 跳过该文件 | degradations |
| 缺 docx/pptx 库 | 改交付 .md 纯文本 | degradations + limitations |
| 无 LaTeX/渲染 | 标注"未渲染预览"，不假装成功 | degradations |
| 写盘失败 | 降级到最小合法 result.json，退出码 0 | errors |
| 数据自相矛盾 | 两条都记录，标 source_conflict，转化稿保留限定或待确认 | sources + uncertainty |
| 体裁与篇幅冲突 | 先保正确与可复核，再压缩 | uncertainty |
| 涉密/未发表 | 只引必要片段，不扩散原文 | degradations/limitations |

## 3. change_log 条目模板

```json
{
  "paragraph": "源文定位，如 materials/paper.md#p3",
  "change_type": "受众适配|删减|术语替换|论断降级|格式调整|合并",
  "reason": "目标读者不需要该方法实现细节，删除的是冗余而非证据",
  "before": "源文片段（逐字）",
  "after": "改后文本",
  "pending": "待人工确认的问题，无则 null"
}
```

## 4. sources 条目模板

```json
{
  "claim": "转化稿中的事实/数字/论断表述",
  "locator": "materials/paper.md#p3",
  "quote": "源文中支撑该条的逐字片段"
}
```

## 5. 确定性要求

- 固定随机种子（本 Skill 无随机数）；同一输入重复运行结果一致。
- 脚本只用 Python 标准库，路径用相对路径（scripts/xxx.py），不依赖作者个人文件或手工操作。
