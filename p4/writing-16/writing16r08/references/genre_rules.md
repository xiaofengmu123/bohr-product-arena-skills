# 体裁映射、论断强度分级与保留优先级

> 本文件是改写时的**规则表**，供 Agent 与原作者复用。与 `lib.py` 中
> `AUDIENCE_PROFILES` / `GENRE_PROFILES` / `STRENGTH_TIERS` 保持一致。

## 1. 受众画像 → 取舍策略

| 受众 | 术语密度 | 行话处理 | 必须保留 | 可删/可压缩 |
|---|---|---|---|---|
| 公众/科普/媒体 | 低 | 缩写首次展开、给类比 | 关键结论、1–2 个核心数字、明确局限 | 方法细节、次要统计、纯修辞 |
| 基金/评审/项目申报 | 中 | 专业术语保留但首次定义 | 目标—路线—验证—风险、关键证据 | 纯科普类比、无关背景 |
| 技术同行 | 高 | 行话可用但首次定义 | 方法参数、条件、样本量、统计口径 | 冗余重复 |
| 政策建议 | 低 | 术语翻译为政策语言 | 可操作结论 + 不确定性边界 | 技术参数 |

通用保留优先级（留得住）：**数值与单位 > 样本量与分组 > 统计口径与比较基准 > 限定条件与范围 > 图表编号与引用 > 关键结论 > 方法要点 > 引用/文献编号 > 论断强度词**。
可删除：冗余重复、与目标读者无关的次要背景、纯修辞铺陈（删前必须写 `change_log` 理由）。

## 2. 体裁结构映射

| 体裁 | 结构要素 | 语气/术语 | 论据边界 |
|---|---|---|---|
| 科普文章 | hook→结论→怎么做（简）→局限→收束 | 通俗、类比 | 保留"可能/初步/有待"，相关不写因果 |
| 新闻/简报 | 核心结论一句→意义→局限→背景 | 简明 | 不确定要显式说 |
| 项目申报 | 目标→背景缺口→技术路线→验证指标→里程碑→风险 | 严谨 | 论断与证据一一对应，不夸大 |
| 技术报告 | 目的→方法→结果→结论→局限 | 术语锁定 | 观察与解释分离，相关不写因果 |
| 政策建议 | 问题→证据→选项→建议→不确定性 | 政策语言 | 明确不确定性边界 |

## 3. 论断强度分级（说得准）

| 强度档 | 关键词（中/英） | 改写约束 |
|---|---|---|
| established 定论 | 证实、表明、显示、demonstrat、confirm、establish | 可保留为定论 |
| preliminary 初步 | 初步、提示、suggest、preliminary、indicate | 不得删"初步/提示" |
| speculative 推测 | 可能、推测、假设、有待、may、might、could、hypothes | 不得升级为定论 |
| correlational 相关 | 相关、关联、correlat、associat、linked | **禁止**改写为因果 |
| causal 因果 | 因果、导致、引起、caus、attribut、driv | 若源文已有因果可保留，但不得把相关升级为因果 |

核心规则：**论断强度只降不升**。改写后强度不得超过源文；`scripts/main.py check` 会机械拦截疑似升级。

## 4. 术语锁定规则

1. 同一概念全文只用一个说法（`glossary.csv` 锁 `canonical`）。
2. 缩写第一次出现写"全称（缩写）"，此后只用缩写；不自行发明缩写。
3. 同义收敛：把多个同义词收敛到 `canonical`，并在 `glossary` 的 `synonyms` 列记录被收敛的词。
4. 跨文体替换只发生在"首次展开/括注/类比"层面，不改科学含义；数值与单位原位保留。
5. 未定义的缩写、公式符号、领域行话 → 若目标读者需要理解则展开，否则标 `pending_human` 请原作者确认译法。

## 5. 证据与改动留痕规范

- 定位：`paper.md#para.3`（段落）、`table.csv:row.4`（表格行）、`fig1` / `p3#caption1`（图/图注）、`sec:3.2`（章节）。
- `evidence_map` 每条：`claim_id + claim + source_id + locator + quote（逐字）+ kind + strength`。
- `change_log` 每条：`id + action（rewrite/compress/delete/translate/merge）+ original_quote + revised_quote + reason + locator`。
- 冲突信息：同一指标两来源不一致 → 两条都记录，标 `source_conflict`，不自行取舍。
- 材料没有的信息 → `pending_human` / `not_reported`，禁止补造。

## 6. 篇幅与格式冲突处理

- 体裁与篇幅冲突（如"写成 200 字科普"但材料是长篇技术报告）→ 保留结论 + 关键数字 + 局限，其余压缩并记 `change_log`。
- 目标读者与体裁不一致（如"面向公众的项目申报"）→ 以**读者理解**为第一优先，术语密度降级，但结构与证据要求仍按体裁保留。
