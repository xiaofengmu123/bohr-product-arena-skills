# 改写规则与检查清单（科研成果转化写作）

本文件是执行 Agent 在成稿、溯源、自检三个环节使用的规则。核心目标：**完成产物，也保留来源**。

## 一、四项验收主线

1. **读得懂**：目标读者不补充背景也能读懂。缩写首次出现必须展开（如 `ORR（氧还原反应）`）；未解释的公式改写为文字或删除并说明；领域行话换成对应读者层的说法，但概念不改义。
2. **留得住**：以下六类"证据项"必须完整保留，删的是冗余（重复句、铺垫、方法细节里的非必要步骤），不是证据：
   - 关键结论（含其原始限定语）
   - 数值 + 单位 + 比较基准（"较对照组提高 12.3%"中的"较对照组"不能丢）
   - 样本量 n、重复次数、置信区间/误差
   - 统计口径（均值±SD？中位数？p 值？检验方法？）
   - 图表编号与"见图 X / 表 Y"引用
   - 文献引用编号/作者-年份
3. **说得准**：论断强度与源文匹配。改写前后强度不得升级或降级：
   - 相关 ≠ 因果；初步结果 ≠ 定论；"表明"与"证实"是两档。
   - 源文是"提示/可能/初步"的，稿子里不得写成"证明/证实/明确"。
   - 同一概念全文只用一个说法（术语表锁定）。
4. **接得住**：每处删改都有 `change_log` 条目：`locator + quote（逐字原文）+ before/after + reason + kind`。原作者可逐段复核。

## 二、论断强度分级（改写对照表）

| 源文措辞 | 强度 | 改写时允许的措辞 | 不允许 |
|---|---|---|---|
| 初步/可能/提示/观察到相关/尚需验证 | 弱 | 初步、提示、观察到相关、尚待更大样本验证 | 证明、证实、明确、确立 |
| 表明/显示/与…相关/伴随 | 中 | 表明、显示、与…相关 | 证实、因果词（导致/促进/驱动） |
| 证实/证明/确立/显著 | 强 | 证实、证明（保持原限定语与样本条件） | 去掉限定语、推广到其他人群 |

任何因果表达（导致/促进/抑制/驱动）只有当源文明确做了因果设计或如此表述时才可沿用，否则一律改为"与…相关/伴随"。

## 三、术语锁定（每案例一张表）

- 定义 canonical 说法 + 缩写 + 首次展开 + 同义词收敛（如"癌症/肿瘤/恶性肿瘤"若源文等同则全稿统一为一个）。
- 表格写入 `evidence_map.json` 的 `terms`：`{canonical: {abbr, first_expansion, variants: []}}`。
- 跨文体替换须成对记录：学术说法 → 读者说法，且保证同一概念两种文体间一一对应。

## 四、证据与溯源格式（写入 evidence_map.json）

- `facts` 每项必含：`locator`（如 `materials/paper.pdf#p3` 或 `materials/paper.txt` + 段落号）、`quote`（逐字原文）、`claim`（改写后表述）、`kind`（number/term/citation/figure/claim）。
- 数字必须连同单位与比较基准一起抽取，禁止只抄数字。
- `uncertainty` 每项：`locator + issue + disposition`。冲突信息两处都记并标 `source_conflict`，不擅自选一个。
- 无法确认的事实写 `pending_human`，不写进稿件正文。

## 五、异常与降级（对应可靠体验·异常）

| 场景 | 处置 |
|---|---|
| 空输入/无材料 | `status=insufficient_evidence`，主稿写"材料不足，无法改写"并列缺口 |
| 坏 JSON / 坏编码 | 记 `errors/degradations`，继续处理其余材料，退出码 0 |
| PDF 提取失败 | 记 `degradations`，改用平台 pdf-text-tool；仍失败原文照录标待核对 |
| 数据自相矛盾 | 记 `uncertainty=source_conflict`，两个都留，待人工裁决 |
| 引用缺失 / 材料涉密 / 未发表 | 记 `pending_human`，不在稿内补造引用或泄露敏感信息 |
| 体裁与篇幅冲突 | 记 `uncertainty`，优先保体裁结构完整，篇幅以契约上限为准 |
| 写盘失败 | 降级到最小合法 result.json（case_id + status + errors） |

## 六、交付前硬核对

- 主稿可打开、可编辑；Office 产物附真实 PDF/PNG 预览。
- result.json 含 case_id + 契约全部字段 + status/sources/uncertainty/change_log。
- 重复运行同一输入结果一致（无随机数、无时间依赖的正文内容）。
- 不写任何源文没有的事实、数字、引用、DOI；不伪造评分。
