# 体裁模板与取舍对照（科研成果转化写作）

按 case.json 指定的体裁/受众选模板。模板只定结构与"可简化 vs 必须保留"，不提供填充示例答案。

## 一、科普文章（学术摘要/论文 → 公众）

结构：一句话结论 → 为什么重要（背景，1-2 句）→ 怎么做（方法要点，无公式）→ 发现什么（关键数据 + 单位 + 比较基准）→ 局限与适用范围（保留限定语）→ 一句话展望。

- 可简化：方法的技术细节、统计检验的完整推导、公式、次级引用。
- 必须保留：样本量、主要数值+单位、对照组/比较基准、局限性（如"仅覆盖某一人群/细胞系"）、图表编号（若源文引用）。
- 术语：缩写首次展开；行话替换为生活化类比，但概念不改义。

## 二、项目申报材料（技术报告/论文 → 立项书）

结构：拟解决的关键问题 → 研究现状与瓶颈（引用编号保留）→ 研究内容与技术路线 → 创新点 → 预期成果与指标 → 可行性/风险与对策。

- 可简化：纯学术讨论段落、冗余背景。
- 必须保留：关键技术指标（数值+单位）、与已有工作的差异（引用编号）、创新点对应的证据来源、风险（即源文局限性）。
- 注意：申报材料的"目标/预期"属于计划性表述，只能基于源文已有基础延伸，不得把"初步结果"写成"已实现"；计划性内容标注为"拟/预期"。

## 三、技术报告（论文/实验记录 → 工程报告）

结构：摘要 → 目的与范围 → 方法与条件 → 结果（数据表/图引用）→ 讨论与局限 → 结论与建议。

- 可简化：领域综述性背景。
- 必须保留：实验条件与参数、全部数据与单位、图/表编号、不确定度/误差、异常数据说明。

## 四、论文摘要改写 / 结构化改写

结构：背景一句 → 目的 → 方法 → 结果（带数据）→ 结论（带强度措辞）。

- 可简化：方法细节、次要数据。
- 必须保留：主要结论的强度措辞、关键数值+单位+样本量、图表编号、结论的限定条件。

## 五、跨文体"可简化 vs 必须保留"总表

| 内容项 | 科普 | 项目申报 | 技术报告 | 摘要 |
|---|---|---|---|---|
| 关键结论 + 限定语 | 保留 | 保留 | 保留 | 保留 |
| 数值 + 单位 + 比较基准 | 保留 | 保留 | 保留 | 保留 |
| 样本量/误差/口径 | 保留 | 保留 | 保留 | 保留（尽量） |
| 图表编号引用 | 保留 | 视要求 | 保留 | 保留 |
| 文献引用 | 简化 | 保留 | 保留 | 保留 |
| 公式 | 文字化 | 视要求 | 保留 | 文字化 |
| 方法细节 | 简化 | 简化 | 保留 | 简化 |
| 综述背景 | 简化 | 简化 | 简化 | 简化 |

若契约给出的体裁不在上表，执行 Agent 按"四项验收主线"自行定结构，并在 `uncertainty` 中说明取舍依据。
