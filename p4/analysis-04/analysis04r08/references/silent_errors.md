# 静默错误清单（结果正确性的前置拦截）

科研数据分析里「跑通了但算错了」比「跑不起来」更危险。本清单是 Step 4 核对时的强制逐条过检项；每一条都要给出「检查方法 + 判定 + 记录位置」，不允许用「看起来合理」代替。

## 1. 缺失值处理（禁：缺失当 0）

- 检查方法：`data_profile.json` 每列 `column_stats.missing` 是否 > 0。
- 判定：凡 missing > 0 的列，任何均值/求和/回归必须先声明缺失策略（删除成对/中位数插补/均值插补/分组内插补），并把策略写入 result.json 的 `uncertainty` 或清洗规则。
- 红线：`missing` 参与统计前未显式处理 = 静默错误。不得把空串、`NA`、`-`、`999` 等当成真实 0。

## 2. 重复记录（禁：未去重就分组统计）

- 检查方法：`data_profile.json` 的 `duplicate_rows` 与 `n_unique_rows`。
- 判定：若 `duplicate_rows > 0`，先判断「整行重复是否应合并」——仪器重复导出应去重，多批次合法样本保留；把判定理由写进 `change_log` 与规则表。
- 红线：分组计数/求和前不去重，会虚高样本量与频数。

## 3. 字段对齐（禁：列名与数据字典对不上）

- 检查方法：`data_profile.json` 的 `field_alignment`，逐字段核对字典语义与真实列。
- 判定：`score=0` 或 `matched_column=None` 的字段必须 `pending_human`，不得按记忆脑补列名（如把「compressive_strength」当成「target」）。
- 红线：用数据字典里的名字去取数据里不存在的列，导致静默取空或 KeyError 掩盖。

## 4. 统计口径与前提（禁：不查前提就报 p 值）

- 描述统计：先确认是「样本」还是「总体」；方差用样本 n−1（`statistics.stdev`），不要手写 n 分母。
- t 检验：报 p 值前检查两组独立性、正态性（Shapiro-Wilk 或 n 足够大时引用 CLT）、方差齐性（Levene/Bartlett）；前提不满足时改用 Welch 校正或 Mann–Whitney U，并在 `uncertainty` 说明。
- 相关/回归：写明是 Pearson 还是 Spearman，r² 与 p 分开报告。
- 有效数字：中间结果保留足够位数，最终报告按最小测量精度取舍，不要用浮点全精度直接写结论。

## 5. 数据库查询（禁：WHERE 条件漏字段）

- 检查方法：把 SQL 的每个 WHERE 条件与任务要求逐条对照，确认没有漏掉约束字段。
- 判定：查询结果行数应与「预期范围 + 原始行数」一致；`data_profile.json` 的 `tables[].n_rows` 作为对照锚点。
- 红线：漏一个 `AND` 条件导致行数偏多，或 `JOIN` 产生笛卡尔积重复行。聚合查询先验证 `COUNT(*)` 与无 WHERE 的基线一致。

## 6. 图表一致性（禁：轴/单位/图例与数据不符）

- 检查方法：每个图元的数值都能指回源数据或统计表（`sources` 的 locator+quote）。
- 判定：坐标轴带单位、图例与分组变量一致、误差棒注明是 SD 还是 SEM、图标题与统计口径一致。
- 红线：图与表数字不一致，或改完数据后忘了重跑图。

## 7. 环境与可复现（禁：隔天重跑数字漂移）

- 检查方法：`runtime` 记录 Python 版本、依赖版本、随机种子、命令行、退出码；随机处固定 `random.seed(42)` 或 `np.random.default_rng(42)`。
- 判定：同一输入两次运行逐字节或逐数字一致；不一致的必须能解释（时间戳、随机不固定等）。
- 红线：随机不固定 + 环境不留档 = 无法复核。

## 8. 失败现场（禁：换代码硬试、掩盖报错）

- 检查方法：每次执行保留 stdout/stderr/退出码；报错先定位根因（缺列、类型、编码、路径、内存）。
- 判定：根因定位后只改一处再跑，改动记入 `change_log`。
- 红线：连续两次同策略失败仍不改方法（见 SKILL.md §6「连续两次同策略失败即换策略」）。

> 以上每条对应 result.json 的 `sources`（证据）、`uncertainty`（不确定点）、`change_log`（动作记录）三者之一。缺证据的结论降级为 `not_reported` 或 `pending_human`，不硬填。
