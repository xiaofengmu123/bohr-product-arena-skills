# 证据溯源、结果/讨论边界、语气校准与降级规则

本文件是写作时逐句执行的规则底稿。运行时以 `/input/case.json` 与 `/input/task.md` 为准，
本文件提供默认规则；冲突时记录到 `uncertainty` 或 `version_boundaries`，不得擅自折中。

## 1. 证据溯源格式（核得了）

`facts_sources` 中每条至少包含：

```json
{
  "claim": "正文中的一句话或一个数字",
  "locator": "材料文件 + 定位（如 material.pdf#p4 或 Fig.2A 或 table1.csv#row3）",
  "quote": "材料中的逐字片段，不得改写",
  "status": "verified | unverified | source_conflict | not_reported | inferred",
  "kind": "number | statistic | term | citation | figure | table | claim"
}
```

规则：

- `quote` 必须是材料内逐字摘录；没有原文可摘就写 `not_reported`，不编造原文。
- 数字必须连同单位与误差棒含义一起记录（例：`mean ± SD`，而非只写 `mean ±`）。
- 同一指标两个来源不一致时，两条都记录并标 `source_conflict`，正文显式说明分歧。
- 引用无法核实标 `unverified`，保留原文位置，不伪造 DOI/URL/作者。
- `inferred` 仅用于"材料内事实的必然推论"（如两值相减），并在正文以相应语气写出；
  超出材料的推测一律归入 `inferred` 且不得写成观察事实。

## 2. 结果段与讨论段边界（分得清）

| 内容 | 结果段（Results） | 讨论段（Discussion） |
|-|-|-|
| 观察到的方向/幅度/显著性/统计量 | 写 | 不重复罗列原始数值 |
| 解释机制、对照文献、说明一致/不一致 | 不写 | 写 |
| 局限与推广边界 | 不写 | 写 |
| 因果/机制推测 | 不写 | 写，且显式标"推测/可能" |

结果段禁用解释性动词（表明/提示/说明/揭示/意味着），只用陈述性动词（增加/降低/差异显著/
无显著差异/观察到）。讨论段禁用新数据，只引用已在结果段出现或材料中给定的数值。

## 3. 语气校准表（说得住）

| 证据强度 | 允许的表述 | 禁止的表述 |
|-|-|-|
| 材料明确写 p<0.05 且结论为显著 | "显著"（附检验量与 p 值） | 不加检验量直接断言 |
| 方向一致但未达显著 | "呈趋势，但未达显著（p=…）" | "显著""证明" |
| 仅某剂量组/子组出现 | "仅在…组观察到"（保留边界） | 推广到全体 |
| 相关关系 | "相关（r=…, p=…）" | "导致""引起""因果" |
| 机制推测 | "可能是…""推测为…" | "证实机制为…" |
| 无依据的总体评价 | 不写 | "首次/国际领先/填补空白/颠覆性" |

语气强度必须与证据强度匹配：小幅、未达显著、单一组的结果不得写成大结论。

## 4. 图表读数卡模板（读得准）

对每张图/表在起草前填写以下字段，缺一项就在 `uncertainty` 记一项：

```text
图/表编号: 多面板编号（如 Fig.2A）与补充材料编号
坐标轴: x 轴/ y 轴名称、单位、刻度（含是否 log 轴）
数据: 每个关键数据点的数值与单位、有效数字位数
误差棒: 含义（SD / SE / CI / IQR / 极差），若未注明标 not_reported
样本量: n 值及分组
统计量: 检验方法、统计量值、p 值、自由度、效应量（材料给了才写）
```

正文数值必须与读数卡一致；材料未给的精度不自行四舍五入，未给的单位不自行换算。

## 5. 禁止的无据措辞清单

`首次、国际领先、国际先进、填补空白、颠覆性、世界首、全球首、首创、重大突破、里程碑`
以及同义夸大表述。出现即由 `selftest.py` 标记为 warning，须复核：要么删除，要么在
`facts_sources` 中给出材料原文支撑。无法支撑则删除。

## 6. 降级策略（禁止编造）

- 材料缺失/字段不明：在 `uncertainty` 或 `version_boundaries` 标"缺失/无法判断"，字段留空或写
  `null`，不补造数值、文献、作者、政策口径。
- 引用无法核实：保留原文位置并标 `unverified`，不伪造 DOI/URL。
- 软件/工具不可用（无 pdftotext、office 渲染等）：如实写 `limitations`，交付纯文本/结构化产物，
  不假装已渲染。
- 输入超长/跨度过大：截取关键段落并在 `uncertainty` 说明"已截断/未覆盖"。
- 运行失败：`status=failed`，`change_log` 记录失败原因与已完成中间产物，`result.json` 仍须落盘。
- 空输入/无材料：`status=insufficient_evidence` 或 `partial`，列出缺口，不用示例填充。
