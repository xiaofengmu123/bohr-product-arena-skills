# 结果与讨论章节写作：规则与检查清单

本文件是 SKILL.md 自检清单的展开依据，运行时以 `/input/case.json` 与 `/input/task.md`
中的实际约束为准；两者冲突时以 case.json 为准，并把冲突写入 `version_boundaries`。

## 0. 写作七要素（结果与讨论专用）

| # | 要素 | 作用 | 对应产物字段 |
|---|------|------|--------------|
| 1 | 图表事实清单 | 逐图/逐表/逐统计输出抽取值、单位、误差棒含义、n、检验量与 p | `facts_sources` |
| 2 | 结果段 | 只陈述观察，不解释、不引文献、不写“因为” | `deliverable`（Results 段） |
| 3 | 讨论段 | 解释、文献对照、机制、局限 | `deliverable`（Discussion 段） |
| 4 | 语气校准 | 趋势/差异/因果表述强度与证据强度一致 | `deliverable` + `uncertainty` |
| 5 | 证据映射 | 每个数值/论断 → locator + 逐字 quote | `facts_sources` / `sources` |
| 6 | 局限与人工确认 | 方法/样本/测量/统计层面的具体局限与待确认项 | `limitations` / `pending_human` |
| 7 | 版本边界 | 修改差异、材料缺口、异常 | `version_boundaries` / `change_log` |

## 1. 读得准（图表读数转写）

- 正文每个数字必须来自实际读取的图/表/统计输出，逐条给 `locator`（文件名 +
  图/表号 + 面板，如 `fig2.pdf#panel-B` 或 `materials/table1.csv#row7`）与逐字 `quote`。
- 记录五元组：值、单位、误差类型（SD/SEM/CI/range，来源未说明则标 `pending_human`）、
  样本量 n、检验量与 p。缺任何一项 → 写 `uncertainty`，不得自行补造。
- 单位换算要显式写出换算过程；有效数字不超过来源精度（可用 `scripts/main.py` 导入
  `core_impl.sigfig_digits` 辅助核对）。
- 误差棒含义不明时禁止默认按 SD 或 SEM 写，必须 `pending_human`。
- 多面板图逐面板读；补充材料编号原样保留（如 Fig. S3A）。
- 读数本身不确定（刻度密、图注缺）时：用“约/approximately”并记 `read_uncertainty`。

## 2. 分得清（结果段 vs 讨论段）

- 结果段只写：方向、幅度、显著性、组间比较、阴性结果——全是观察，无“因为/表明/提示
  机制/与文献一致”。
- 讨论段才写：解释、机制推测、文献对照（一致/不一致/可能原因）、局限。
- 每段开头可加角色标记（不写入正文，只用于自检）：`[R]` 结果、`[D]` 讨论。
- 自检动作：结果段内出现“解释/机制/提示/可能原因/与 X 一致”等词 → 移入讨论段或改写。

## 3. 说得住（语气与证据强度匹配）

语气阶梯（自上而下证据要求递减）：

| 级别 | 表述 | 证据门槛 |
|------|------|----------|
| 事实 | “在 48 h，处理组活力为 62 ± 5%” | 有值 + n + 误差 |
| 显著差异 | “显著低于对照（p=0.031, n=3）” | 报告检验、p、n |
| 趋势未达显著 | “呈下降趋势，但未达显著（p=0.08）” | 必须写“未达显著”+ p |
| 亚组/剂量受限 | “仅在高剂量组观察到” | 必须写出“仅/只有”与亚组 |
| 相关 | “X 与 Y 相关（r=…）” | 报告相关系数或检验 |
| 预测 | “X 可预测 Y” | 需模型/交叉验证，不可只凭相关 |
| 因果 | “X 导致 Y” | 需干预/实验设计支撑，否则改写为相关 |
| 机制推测 | “可能通过…介导” | 必须标“可能/推测”，不写结论语气 |

禁词（无据时禁止，有据时须给 locator + quote 后保留）：首次、国际领先、填补空白、
颠覆性、革命性、世界第一、重大突破、唯一。脚本 `forbid_scan` 会自动扫描并给出告警。

## 4. 核得了（证据映射）

每条 `facts_sources` / `sources` 项的最小结构：

```json
{
  "claim_id": "R2-1",
  "claim": "48 h 处理组活力 62%",
  "locator": "fig2.pdf#panel-B",
  "quote": "cell viability 62 ± 5% (n=3)",
  "kind": "figure | table | stat_output | reference | author_inference",
  "status": "verified | unverified | pending_human | source_conflict",
  "notes": ""
}
```

- `kind=author_inference` 专用于“材料未明说、由写作者推断”的内容，正文不得冒充事实。
- 讨论段引用文献：若原文献在材料中，给 locator；若找不到，标 `unverified` 并写
  `pending_human`，**不得伪造 DOI/URL**。
- 同一指标两个来源不一致：两者都记录并标 `source_conflict`，正文取稳妥口径并说明。

## 5. 一致性检查表（结果↔讨论↔图表↔局限）

- [ ] 结果段每个数字都能在图/表/统计输出中找到原文（不新增材料外事实）。
- [ ] 讨论段每条论断要么指向本研究数据（locator），要么指向具体文献（locator 或
      `unverified`），没有“只堆引用不讲关系”。
- [ ] 趋势/差异表述的方向、幅度、p、n 与图表一致；阴性结果如实交代。
- [ ] 因果表述与设计强度一致；机制推测已标“可能/推测”。
- [ ] 局限写到方法/样本/测量/统计层面，不是“样本量小”这种空泛评价。
- [ ] `deliverable` 满足 case.json 指定的体裁、受众、格式（含双语/引用格式要求）。

## 6. 引用核验

- 引用格式按 case.json 要求（如期刊样式）；未给样式时保持材料原文样式。
- 编号引用与文末参考文献一一对应；找不到出处的引用标 `unverified`。
- 不因文件名或领域标签补造作者、年份、DOI、期刊名。
