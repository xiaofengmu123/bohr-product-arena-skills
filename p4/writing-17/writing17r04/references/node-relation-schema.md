# 节点与关系规范（导图抽取规则）

本文件定义 `mindmap.json` 中节点类型、关系类型、粒度与证据标注的约定。Agent 抽取时据此保持层级一致、同级粒度一致、关系有据。

## 1. 节点类型（`type`）

| 类型 | 含义 | 何时使用 |
|-|-|-|
| `root` | 导图根节点，唯一 | 主题/材料的研究对象，全图入口 |
| `concept` | 核心概念/术语 | 材料定义或反复使用的关键概念 |
| `question` | 研究问题/子问题 | 材料明示或可推断的"要回答什么" |
| `hypothesis` | 假设/预期 | 材料中的假设、预期结果 |
| `method` | 方法/步骤/工具 | 实验设计、算法、测量方式、流程 |
| `material` | 材料/数据/对象 | 样本、数据集、试剂、语料 |
| `evidence` | 证据/数值/图表 | 可定位到页码/段落的数字与结论 |
| `result` | 结果/发现 | 材料报告的结果性陈述 |
| `conclusion` | 结论/推断 | 作者结论或归纳 |
| `task` | 任务/待办/交付 | 目标、里程碑、责任、截止时间 |
| `risk` | 风险/限制条件 | 材料声明的风险、限制、依赖 |
| `gap` | 研究空白/不足 | 材料指出的未知、缺口 |
| `limitation` | 局限/边界 | 方法或结论的适用范围限制 |
| `decision` | 决策/分歧结论 | 会议结论、取舍、分歧点 |
| `other` | 其他 | 上述都不匹配且确需保留时 |

## 2. 关系类型（`rel`，用于 `edges`）

| 关系 | 含义 | 方向注意 |
|-|-|-|
| `part_of` | 属于/组成 | 子 → 父 |
| `causal` | 因果 | 原因 → 结果 |
| `depends_on` | 依赖 | 后者 → 前者 |
| `supports` | 支持/证实 | 证据 → 论点 |
| `contradicts` | 矛盾/冲突 | 证据 → 被驳论点 |
| `contrasts` | 对比/差异 | 一方 → 另一方 |
| `cites` | 引用 | 节点 → 被引来源 |
| `temporal` | 时间先后 | 先 → 后 |
| `compares` | 比较 | 比较主体 → 参照 |
| `example_of` | 例证 | 例子 → 概念 |
| `other` | 其他 | 仅在确有必要且材料有依据时 |

只有材料中**有依据**的关系才写入 `edges`；层级包含关系用 `parent`（树），不要重复用 `part_of` 表示父子。

## 3. 层级与粒度

- 根节点唯一；第二层一般为稳定大类（问题/方法/证据/结论/任务/风险），避免分类交叉。
- 同一父节点下的兄弟节点粒度应相近；单个节点只表达一个语义单元，不做长句堆叠。
- 装饰性、客套、背景铺陈词语不建节点；只保留承载概念、问题、方法、证据、结论、任务或风险的内容。
- 每个分支深度通常 ≤ 5；更深时考虑是否把同级节点合并或上移。

## 4. 证据标注（`evidence`）

每个节点/关系都可带 `evidence` 对象：

```json
{"locator": "materials/paper.md#p3", "quote": "逐字引用的原文片段"}
```

规则：
- `locator` 必须指向真实材料位置（文件名 + 段落/页码/节），不得虚构。
- `quote` 必须是从材料**逐字复制**的原文，不得改写。
- `evidence_type` 三分类（写入 result.json 的 `fact_source_map`）：
  - `fact`：材料直接陈述的事实/数字/引用；
  - `summary`：对材料的概括（非逐字）；
  - `inference`：Agent 的推断/归纳，需在 `uncertainty` 或 `pending_human` 中说明。
- 概括与推断不得冒充逐字事实；缺材料就用 `material_gaps` 或 `pending_human` 标注，不编造。

## 5. 结果回填约定

抽取完成后，把节点与关系规范化写入 `mindmap.json`（见 `scripts/render.py` 顶部 schema），再运行 `python3 scripts/render.py --spec <work>/mindmap.json --output /app/output` 生成可编辑产物。
