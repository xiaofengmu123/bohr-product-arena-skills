# 长文档改稿检查清单（Agent 逐条执行，产出与评分维度对应）

本清单用于“依据科研材料编辑既有章节/生成新章节”的完整闭环。每条对应评分考察点，
完成后在 result.json 的 change_log 或 check 摘要中留痕。

## A. 任务理解（任务完成度 · 15 分）

- [ ] 已读取 organizer-edit-workorder.json（若存在），逐条列出 edit target、action、reason。
- [ ] 已读取 task.md 的体裁、受众、格式约束（学位论文/综述/方法/结果/讨论等）。
- [ ] 每个 edit target 都有唯一 id，且能映射到“改哪个文件/章节、怎么改、为什么改”。
- [ ] 输出的是可编辑章节文本（.md 优先），不是“写作建议”或“提示词”。

## B. 事实与来源一致（结果正确性 · 15 分）

- [ ] 数字、术语、符号、章节/图/表编号与给定材料逐字一致，不新增材料外事实。
- [ ] 每条引用对应一个真实存在的参考文献条目；引用但无条目 → 标注 `citation_undefined`。
- [ ] 术语与缩写首次出现给出定义，之后统一；不一致处已修正或标注。
- [ ] 未找到原文的引用、来源冲突 → 写入 uncertainty 或 pending_human，不杜撰。

## C. 完整性（结果完整性 · 5 分）

- [ ] 提纲要求的章节全部产出；必要论证要素（研究问题、方法、结果、讨论、局限）齐全。
- [ ] 图表、参考文献、附录等著录项按体裁要求补齐或明确标注缺失。

## D. 可核验性（结果可核验性 · 5 分）

- [ ] 每个关键论断/数值/引用都写入 evidence_map（locator + 逐字 quote）。
- [ ] 每次改动写入 change_log（file、before、after、reason），可回退、可比较。
- [ ] result.json 含 case_id、output_contract 全部字段、status/sources/uncertainty/change_log。

## E. 跨章节一致性（质量增益 · 15 分）

- [ ] 已运行 `scripts/consistency.py`，处理 severity=warning 及以上问题。
- [ ] 章节/图/表/公式编号无缺口、无重复。
- [ ] 同一概念无多种写法；同一术语无重复且不一致的定义；前后结论无数值冲突。

## F. 可编辑性（质量增益 / 使用增益）

- [ ] 只改需要改的位置，保留作者原句与既有表述；能说明“改了什么、为什么改”。
- [ ] 输出保留原文件结构，未改段落原样保留，未做全文重写。

## G. 异常与降级（异常处理 · 3 分）

- [ ] 材料缺失 → status 用 `insufficient_evidence`，列出缺口；不编造。
- [ ] 文档格式不支持/超长截断 → 记录到 degradations；PDF 无文本层则说明并走 OCR/渲染。
- [ ] 引用找不到原文、章节结论冲突、编号不连续 → 逐一记录，不静默丢弃。

## H. 时间与请求预算（运行稳定性）

- [ ] 前 3 分钟已落盘 partial result.json 骨架（scripts/main.py skeleton）。
- [ ] 总请求 ≤ 64 次、总时长 ≤ 900 秒；每轮只做增量改进，不从头重写。
