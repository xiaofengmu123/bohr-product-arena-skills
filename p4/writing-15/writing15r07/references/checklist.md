# 自检清单与评分维度对照

交付前逐条勾选。每项只对当前案例的实际产物打勾，未通过就修复或标 `limitations`。

## 实际效果（40 分）

- [ ] 任务完成度：按 case.json 的 output_contract 与 task.md 的体裁/受众/格式真正写出了可用章节，而非给通用写作建议。
- [ ] 结果正确性：每条论断与其引用文献对得上；数据、术语、符号、章节/图表/公式编号与原文一致。
- [ ] 结果完整性：研究问题、方法、结果、讨论、局限齐全；图表、参考文献、附录（如要求）齐全。
- [ ] 结果可核验性：每段文字可回溯到提纲条目、原始材料、文献与版本记录（见 evidence 字段）。

## 使用增益（25 分）

- [ ] 质量增益：跨章节术语、编号、交叉引用由 `scripts/consistency.py` 自动检出并修复。
- [ ] 效率增益：不反复通读全文手工统一术语/编号/引用，检查脚本一次跑全稿。
- [ ] 增益可验证：同稿同输入重复运行，`consistency_report.json` 结果一致（确定性）。

## 创新增益（15 分）

- [ ] 新增能力：契约抽取 + 证据映射 + 一致性检查形成可复现闭环，非 LLM 口头自述。
- [ ] 方法改进：`result.json` 骨架先落盘（partial），证据逐条 append，支持增量与断点续跑。
- [ ] 创新证据：scripts 只依赖标准库、路径相对、可在干净环境复跑。

## 可靠体验（10 分）

- [ ] 调用易用：`python3 -B scripts/main.py --help` 与 `consistency.py --help` 退出码 0。
- [ ] 运行稳定：综述/方法/结果/讨论等不同章节类型、不同篇幅均能产出；重复运行结果一致。
- [ ] 异常处理：空输入 → `insufficient_evidence`；坏 JSON/坏编码降级；引用找不到原文标 `pending_human`；编号不连续、冲突、超长截断均被记录。

## 生态贡献（10 分）

- [ ] 文档完整：说明、依赖（仅标准库）、配置、适用范围、篇幅上限、失败模式、维护信息齐全。
- [ ] 资源可复用：脚本、术语表/引用表模板、章节检查清单可直接被他人复用。
- [ ] 分享价值：沉淀了可复用的长文档写作案例与一致性检查清单。

## 最终 `result.json` 硬校验（脚本 finalize 已含）

- [ ] `case_id` 存在且非空。
- [ ] `status ∈ {ok, partial, insufficient_evidence, input_error}`。
- [ ] output_contract 的全部键都在，缺值补 null/[]，未改名、未删未知键。
- [ ] 每条 evidence 都有 locator 和逐字 quote。
- [ ] 每条 change_log 都有 before 或 after（可比较、可回退）。
- [ ] `sources`、`uncertainty`、`change_log` 字段齐全。
