# 长文档写作检查清单

逐条勾选，对应评分维度"实际效果 / 可靠体验 / 使用增益"。

## A. 读材料与任务（立得住）

- [ ] 已读 case.json 与 task.md，明确受众、文体、篇幅与格式约束。
- [ ] 已列出事实底稿中的研究问题、方法、结果、讨论、局限五个论证要素。
- [ ] 已按提纲建立"每节回答什么问题、需要哪些证据"的映射。
- [ ] 章节顺序、论证链条、字数分配与提纲一致，而非材料堆砌。

## B. 跨章节一致性（连得上）

- [ ] 术语表/符号表已建立，同一概念全文写法统一。
- [ ] 首次出现的缩写已给出全称定义，且后续不再重复定义。
- [ ] 图/表/公式编号连续，正文交叉引用与图表标题一致。
- [ ] 改动一处后，受影响段落已用 `scripts/check_consistency.py` 复查。

## C. 修改与版本（改得动）

- [ ] 局部修改只动必要处，保留作者原意与既有表述。
- [ ] 每条改动写入 `change_log`（scope/action/reason/diff/reversible）。
- [ ] 机器改写句与作者原句的差异可比较、可回退。

## D. 引用与溯源（查得清）

- [ ] 每条论断/数字/术语/引用可回溯到材料 locator + 逐字 quote。
- [ ] 引用文献能在材料或参考文献列表中找到；找不到的标 `pending_human`。
- [ ] 引用与结论未被改写；改写处已在 change_log 说明。
- [ ] 冲突信息两侧都记录并标 `source_conflict`。

## E. 产物与终检

- [ ] 主产物可编辑（.md/.docx/.pptx/.xlsx），并有真实 PDF/PNG 预览。
- [ ] result.json 含 case_id、status、全部 output_contract 字段、sources/uncertainty/change_log。
- [ ] 未确认项明确标注，不冒充已完成。
- [ ] 两次运行同一输入结果一致（固定随机种子、确定性布局）。
