# 写作与一致性检查清单（模板，可复用）

按「立得住 / 连得上 / 改得动 / 查得清」四目标逐条执行；每完成一项在产物中留痕，
便于 `evidence_map` 与 `change_log` 回溯。

## 一、立得住：章节规划

- [ ] 从 `case.json`/`task.md`/`organizer-edit-workorder.json` 提取研究问题、受众、文体、格式与编辑目标。
- [ ] 写出章节提纲：每节写明「本节回答什么 / 需要哪些证据 / 大致字数」，与论证链对应。
- [ ] 检查是否有章节重复或断裂；提纲与正文一一映射（标题编号连续，见 `check.py`）。

## 二、连得上：跨章节一致性

- [ ] 维护术语表（术语 / 缩写 / 定义 / 首次出现章节），同一概念不换写法、不重复定义。
- [ ] 维护符号表（符号 / 含义 / 单位 / 定义位置）。
- [ ] 图表与公式编号连续；正文引用「图 X / 表 X / 公式 (n)」都有对应标题（`check.py` 自动查）。
- [ ] 结论清单：前后章结论不互相矛盾；改动一处后定位受影响的段落并回改。

## 三、改得动：可编辑与可回退

- [ ] 产物用 `.md`（或用户指定的 `.docx`）交付，可打开、可编辑、可继续修改。
- [ ] 每次修改只动需要动处，保留作者原句；差异写进 `change_log`（改前原文 → 改后文本 → 原因）。
- [ ] 未确认的改写项标 `pending_human`，不擅自替换作者已定论表述。

## 四、查得清：来源与引用

- [ ] 每条论断/数据/术语/图表引用都有 `evidence_map` 条目（locator + 逐字 quote）。
- [ ] 引用标记 `[n]` 与参考文献表一一对应；作者-年份引用与文献条目匹配（`check.py` 自动查）。
- [ ] 不新增材料外事实；材料不足、来源冲突、找不到原文分别标 `unverified`/`conflict`/`pending`。
- [ ] 交付 `sources` 清单 + `status` + `uncertainty` + `limitations`，他人可独立复核。

## 五、通用产物模板（示意，非正式答案）

章节骨架（示例，须据案例填充）：

```text
# 第X章 标题
## X.1 研究问题与背景（回答什么 / 证据来源）
## X.2 方法
## X.3 结果
## X.4 讨论与局限
```

术语表模板（`glossary.md`，示意）：

| 术语 | 缩写 | 定义 | 首次出现 |
|---|---|---|---|
| … | … | … | §X.Y |

引用表模板（`references.md`，示意）：

| 编号 | 文献 | 在文中的论断 | 来源定位 |
|---|---|---|---|
| [1] | … | … | materials/… L… |

以上均为格式示例，正式运行须按案例实际材料填写，禁止预填案例答案。
