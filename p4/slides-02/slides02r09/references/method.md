# 方法与边界说明（method）

## 1. 核心设计：先落骨架、事实冻结、逐页增量
本包把「可靠交付」建立在三个机制上，而非靠 Agent 自觉：
1. **前 3 分钟落骨架**：`scaffold` 先写一版合法的 partial result.json，任何中途异常都不留空产物。
2. **事实冻结**：关键数字/图注/引用先以「locator + 逐字 quote」存入 facts.json，页面只绑定事实 ID。这是对「按印象取整、抄错数字」的机制性防御，`check` 强制校验 quote 与 locator 非空。
3. **增量记录**：`record` 统一追加 change/source/fact/evidence/version，最终 `finalize` 合并成 result.json 的 sources/change_log 等保留字段；除字段损坏外不重写既有骨架。

## 2. 页序规划方法
按叙事角色排页，而不是按论文章节顺序照搬：hook（为什么关心）→ question（研究问题）→ method（压到 3–5 条）→ results（按证据强弱与图引用排序）→ limits（限制与结论边界）。每页只承担一个角色、一个主张、若干条证据引用，并写清数据出处与字数预算。图的先后由「哪张图支撑当前主张」决定，不由图号顺序决定。

## 3. 模板槽位填充
只编辑模板占位符与版式，不新建母版、不改配色/页脚；槽位不足时映射到最近似版式并记录偏差。这避免「改一页改坏母版」的失败模式。

## 4. 图表数据绑定
区分「可重绘」与「只能引用原图」：有可复核数据表/向量数据时才重绘并保留数据出处；纯位图只引用原图+图号/页码定位，绝不重绘假曲线、不补数值。

## 5. 局部编辑边界
单响应 16384 token 上限下，一次只处理一页或一个校验点；改前用 `record --kind version` 存快照（含 sha256 摘要），保证可回退、可说明哪一版是交付版。

## 6. 与基础 Agent 的差异（增益机制）
- 质量：事实绑定让页面数字只能来自冻结的逐字 quote，减少抄写错误。
- 效率：骨架先行 + 单页增量，减少整稿重排；版本快照减少导出复查后的返工。
- 可核验：check 产出 self_check.json，change_log 记录每次动作，第三方可复跑复核。

## 7. 边界
本包只解决「材料 → 学术演示稿 + 可复核记录」这一单一流程；不做科研绘图算法、不做 PPT 软件本身、不做通用大而全的抽象。没有真实材料时输出材料不足，而非示例填充。
