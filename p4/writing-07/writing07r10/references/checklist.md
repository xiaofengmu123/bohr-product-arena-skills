# 写作规则与交付自检清单

本文档分两部分：写作规则（正文怎么写得“立得住/分得清/说得实/对得上”）与交付前自检清单（对应评分维度，逐条可勾选）。

## 1. 写作规则

### 1.1 四段结构与承接

成稿 `manuscript.md` 必须四段齐全且彼此承接，缺一段即判 `partial`：

1. **研究背景**：从领域脉络、具体问题、技术约束交代“为什么现在值得做”，指向**具体的未解决问题**，禁止“近年来受到广泛关注”式空转。
2. **相关工作**：按问题设定 / 方法路线 / 数据与评价方式**分组比较**，在同一维度比较各工作的取舍；不按时间顺序罗列，不逐篇摘要拼接。
3. **研究空白**：由已引工作的共同限制 / 未覆盖场景 / 相互冲突结论**推出**，并写明本文如何填补；无法由文献推出的判断标注“作者判断”。
4. **贡献**：把方法、实验、结论压缩为可核对条目，每条可映射到正文方法/图表/结果，不夸大适用范围。

### 1.2 证据与引用

- 每个事实句挂 `[S#]` 锚点；`S#` 与台账 `sources.key` 一一对应。
- 数字 / 单位 / 统计量逐字复用，材料没有的不补，写 `MATERIAL GAP` 或 `not_reported`。
- 转述保留原文结论、适用条件与局限；引用落在具体论断上，不是段尾堆叠。
- 引用只用材料中真实出现的来源；元数据缺失写 `pending_human`，不造 DOI / 作者 / 年份。

### 1.3 冲突与空白

- 同一指标两来源不一致：两条都记入台账 `conflicts`，标 `source_conflict`，正文按保留原文结论处理并注明不一致。
- 空白推导链条要在 `claims` 中可回溯：`gap` 条目注明所依据的 `source_ref` 与 `status=author_judgment` 与否。

### 1.4 语言与格式

- 保持术语 / 数字 / 引用原位，仅换语时限定强度不变；中文成稿用正式书面语，避免“我/你”。
- 目标期刊格式未知时采用作者—年份并在 `uncertainty` 声明假设。

## 2. 交付前自检清单（对应评分维度）

执行 `python3 -B scripts/selftest.py` 跑脚本级自检后，逐条人工勾选：

### 实际效果（40 分）

- [ ] manuscript.md 四段（研究背景 / 相关工作 / 研究空白 / 贡献）齐全且承接，可直接进入论文。
- [ ] 背景指向具体未解决问题，无“近年来受到广泛关注”式空转。
- [ ] 相关工作按问题 / 方法 / 技术路线分组，含问题设定、方法、数据与评价维度。
- [ ] 每条引用落在具体论断上，转述与原文一致，元数据真实可核对。
- [ ] 空白由已引文献缺口推出，并写明本文填补方式；作者判断已标注。
- [ ] 每条贡献可映射到正文方法 / 图表 / 结果，不夸大适用范围。
- [ ] 背景、相关工作、空白、贡献、引用覆盖五要素齐全；主要方法路线、关键工作、必要字段（作者 / 年份 / 来源）已覆盖。
- [ ] 每条引用可回到来源；分组依据、空白推导、贡献对照可独立复核。

### 使用增益（25 分）

- [ ] 同一材料下，成稿按“分组比较 + 空白推导 + 贡献对照”产出，而非逐篇罗列；引用与论断绑定（优于无 Skill 的基础 Agent）。
- [ ] 一次起草即产出台账 + 稿件，避免逐条核对引用的多轮返工；`verify` 一键复核锚点与合同字段。

### 创新增益（15 分）

- [ ] 使用了版本化**证据台账**作为唯一中间态（区别于散落的 facts.md / evidence_map 双份维护）。
- [ ] 使用了**合同先行**：先归一化 output_contract 再落骨架，保证合同字段一个不漏。
- [ ] 使用了**校验顺序分离**：verify 先查合同合规、再查内容完整性，错误可定位到字段级。

### 可靠体验（10 分）

- [ ] 空输入目录：脚本退出码 0，写出 `insufficient_evidence`。
- [ ] 坏 JSON / 坏编码：记录到 `errors` / `degradations`，其余材料继续处理。
- [ ] 缺参数：脚本缺省指向 `/input`、`/app/output`、`/app/work`。
- [ ] 重复运行：两次结果一致（无随机或已固定种子）。
- [ ] 在“写引言”“整理相关工作”“补引用”“核对贡献”等指令下正确触发。

### 生态贡献（10 分）

- [ ] 文档含用途、适用条件、调用方式、输入输出、异常处理、依赖（仅标准库）、限制与维护信息。
- [ ] 台账 schema、分组模板、核对清单可被他人复用。
- [ ] 最小调用示例已给出且标明为示例，不冒充正式案例结果。

## 3. 最小调用示例（示例，非正式案例）

```bash
python3 -B scripts/main.py discover --input /input --work /app/work --output /app/output
python3 -B scripts/main.py scaffold --input /input --work /app/work --output /app/output
# Agent 在 discover 与 scaffold 之间/之后读材料，写 work/ledger.json 与 /app/output/manuscript.md，
# 并回填 /app/output/result.json 的合同字段与 status
python3 -B scripts/main.py verify --input /input --work /app/work --output /app/output
python3 -B scripts/selftest.py   # 交付前脚本自检，退出码 0
```
