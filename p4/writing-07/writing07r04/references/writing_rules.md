# 写作与证据规则：降级与不确定性显式化

本文档是 SKILL.md 第 5、7 节的展开细则，Agent 起草与核对时必须遵守。

## 1. 置信分级（每个事实句必须标注其一）

| 级别 | 标注 | 含义 | 证据要求 |
|---|---|---|---|
| `quote` | `[S#]` | 逐字引用材料原文 | `quote` 必须与材料逐字一致，含数字、单位、限定词 |
| `paraphrase` | `[S#]` | 转述材料结论 | 保留原文结论、适用条件与局限，不升格强度 |
| `inferred` | `[S#]` | 多份材料归纳推断 | 在 `uncertainty` 说明推理链与前提 |
| `author_judgment` | `[作者判断]` | 材料外作者观点 | 不得挂 `[S#]`，必须显式标注并说明依据或写“无直接材料” |
| `gap` | `MATERIAL GAP` / `not_reported` | 材料缺失，无法成句 | 不补造；写入 `limitations` |

规则：

- `quote` 与 `paraphrase` 是唯一可承载事实断言的级别；`inferred` 必须同时给出前提来源。
- 数字、单位、百分比、p 值、样本量等**逐字复用**，材料没有的不补。
- 升格禁令：原文“可能/初步表明/在某些条件下”不得改写为“证实/普遍成立”。
- 降格允许且鼓励：不确定就写不确定，写在 `uncertainty`，不藏在正文里。

## 2. 四段结构与写作要求

### 研究背景（立得住）
- 从领域脉络、具体问题与技术约束入手，交代“为什么现在值得做”。
- 禁止“近年来受到广泛关注”“具有重要研究意义”式空转；必须指向具体未解决问题。
- 每个背景事实句挂 `[S#]`；领域判断无法溯源时写 `[作者判断]`。

### 相关工作（分得清）
- 按问题设定 / 方法路线 / 数据与评价方式分组，不按时间罗列。
- 组内按同一维度比较取舍：每组给出“问题设定—方法—数据—评价”四要素中材料可支撑的部分。
- 转述保留原文结论、适用条件与局限；不同来源结论冲突时并列并标 `[存疑]`。

### 研究空白（说得实）
- 空白只能由已引工作的共同限制、未覆盖场景或相互冲突结论推出。
- 每条空白必须写出“本文如何填补”；无法由文献推出的判断标注 `[作者判断]`。
- 若空白无依据，写 `MATERIAL GAP` 并计入 `limitations`，不硬造空白。

### 贡献（对得上）
- 把方法、实验、结论压缩为可核对条目；每条贡献必须能映射到正文方法/图表/结果。
- 不夸大适用范围；映射关系写入 `change_log` 或 `evidence_map` 的对照注记。

## 3. 来源与证据映射

- `locator` 形如 `materials/paper.md#p3`（段落/页码）；PDF 用 `materials/foo.pdf#pN`。
- `quote` 为材料**逐字片段**；非逐字但可核对的转述用 `paraphrase`，`quote` 字段仍放原文关键句。
- 冲突信息不隐藏：同一指标两个来源不一致时，两条都记并标 `source_conflict`。
- 引用元数据（作者/年份/期刊/DOI）只用材料中真实出现的；缺失写 `pending_human`，绝不编造。

## 4. limitations 与 uncertainty 写作规范

`limitations` 每项四要素：

```json
{"scope": "相关工作中的数据集评价维度",
 "missing": "三篇工作未报告消融实验",
 "impact": "无法逐项核对方法增益来源",
 "disposition": "正文标 MATERIAL GAP，留待人工补材料"}
```

`uncertainty` 每项三要素：

```json
{"item": "X 方法的适用条件",
 "reason": "来源 A 与 B 表述不一致（source_conflict）",
 "confidence": "low"}
```

写入顺序：先 `limitations`（缺口清单），再 `uncertainty`（置信判断），二者不互相替代。

## 5. 编造防火墙（硬性禁令）

以下行为一律禁止，违者 `status` 不得为 `ok`：

1. 补造材料中不存在的数字、单位、p 值、样本量、准确率等统计量。
2. 虚构作者、年份、期刊、DOI、URL、评测分数或基准结果。
3. 把 `MATERIAL GAP` 用示例内容填充冒充真实材料。
4. 声称“经实验验证”而材料中没有对应方法/图表/结果。
5. 对缺失软件状态（如 PDF 解析失败）伪装成功并给出未经提取的“原文”。

校验脚本会在主产物中检查占位空话（`Lorem ipsum`、`TODO`、`此处插入`、`示例数据`、`占位`）并告警；Agent 交付前须清除。

## 6. 引用格式

- 案例指定格式优先；未指定缺省作者—年份（如 `(Author, 2020)`），可改数字式 `[1]`（改动记 `change_log`）。
- 目标期刊格式未知时，采用作者—年份并在 `uncertainty` 声明假设，不冒充特定格式。
- 语言切换：术语/数字/引用原位，仅换语，限定强度不变。

## 7. 确定性

- 无随机成分；若案例要求改写措辞的多样性，固定 `random.seed(0)` 并记入 `change_log`。
- 两次运行同一输入应产出一致的结果结构与事实内容（`runtime` 时间戳除外）。
